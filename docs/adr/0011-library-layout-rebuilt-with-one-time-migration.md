# 库目录按新设计重排，旧库一次性迁移

文件仍是唯一数据源（ADR-0002），但应用不再迁就旧布局：库根改为 `拆书/`、`灵感库/`（六格）、`书/`（可以很多本）、`随身本/` 四处；旧库经一次性迁移进入新布局，迁移前自动整库备份，迁移后不再兼容读取旧布局。修订 ADR-0002 中"识别现有布局、不强制搬动"一条：库仍可以指向 Obsidian vault 里的一个文件夹，但文件夹内部的结构由应用管理。

灵感库按"将来会落进骨架的哪一层"分六格——胚子、故事、爽点、人物、设定、字句——而不是按"它是什么"分九类：翻库时问的是"我现在缺什么"。旧九类逐条迁入：故事卡 → 故事；金手指卡、题材卡、书名卡 → 胚子（原类别留作标签）；角色卡 → 人物；组织卡、世界观卡 → 设定；片段卡、技法卡 → 字句；未分类 → 随身本。

## Considered Options

- **继续兼容读取旧布局**（否决）：旧布局按数据模型摆放（九类卡片、构思十几个文件），兼容读取会让每个新功能都背着两套结构。
- **取消灵感库，只留随身本**（第一轮方案，第二轮推翻）：灵感攒到上百条后无法筛选，不属于哪一本书、可以换皮复用的灵感没有归宿。

## Consequences

迁移是一次性、可回滚（靠备份）的动作，必须先在旧库副本上验收。
