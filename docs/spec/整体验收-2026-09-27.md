## 未通过项

### A1 · P1：保存等待期间新增文字，切章可能丢失

位置：`app/src/WritingPage.tsx:716`、`:758`、`:787`、`:803`。

操作顺序：第一章未保存 → 点第二章 → 保存请求发出后继续输入 → 保存返回。

`saveNow` 已识别编辑器内容与本次保存快照不同，会保留脏标记，但仍返回 `true`。`openChapter` 把这个返回值当作可以切章，随即载入第二章并清除当前编辑状态。保存往返期间输入的文字既不在第一章文件中，也不再保留在编辑器里。返回项目、搜索跳转等复用保存返回值的路径同样需要检查。

复现：`node .scratch/acceptance-20260927/save-navigation-repro.cjs`。正常切章为对照；延迟保存期间追加文字时，返回成功而第一章保存内容不含新增文字。

修复验收要求：准备卸载或替换编辑器前，必须确保最新编辑版本已经保存；保存过程中又有编辑时继续完成保存或保持原编辑器。新增回归应覆盖切章、返回和搜索跳转。

### A2 · P1：更换库位置后继续编辑旧库对象

位置：`app/src/App.tsx:169`、`app/src/Writing.tsx:78`、`:162`、`app/src/Ideation.tsx:95`。

“设置 → 库与数据 → 更改库位置”只修改当前库路径，没有退出或重新绑定已打开的拆书稿、构思项目和书写项目。书写扫描刷新列表却保留 `open.project`；构思扫描在新库找不到旧项目时也保留旧项目；拆书编辑器仍以旧 `openBook.primaryMd` 挂载。

后果：当前库已经显示为 B，编辑器却仍读写 A 的对象；书写速记还会把新库根与旧项目一同提交，后端将因归属不一致拒绝保存。不能据此断言速记被写入错误库，后端对此有校验。

复现：`node .scratch/acceptance-20260927/library-switch-repro.cjs`。更换为空新库并完成扫描后，当前库是新库，已打开项目仍是旧库路径。

修复验收要求：切库前保存并处理冲突；切库后各板块只保留新库对象，取消旧库迟到的扫描响应。至少验证拆书、构思、书写三处及新库速记。
