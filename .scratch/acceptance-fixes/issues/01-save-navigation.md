## Parent

#76 整体验收修复与终验；对应用户故事 1–10，以及 A1。

## What to build

拆书和书写编辑器在切章、返回或打开搜索结果时，先确保最新文字落盘；保存等待期间继续输入也不会丢字。不能安全离开时保留当前对象、原文字及可继续操作的编辑器。

在本条完整行为中统一已有保存和导航保护约定，不单独交付没有用户行为的重构。一次保存请求成功不等于当前缓冲已保存；正常自动保存策略保持兼容。

## Acceptance criteria

- [ ] 正常切章、返回项目、拆书返回与全局搜索跳转在最新文字保存后继续，不增加每次导航的常规确认弹窗。
- [ ] 通过可控 IPC 延迟，在保存请求发出后继续输入；新增文字全部落盘后才离开，或留在原编辑器并明确导航尚未完成。
- [ ] 已有自动保存进行中、连续点击不同目标及旧章节读取迟到时，不丢字、不加载陈旧目的地、不将旧保存响应应用到新对象。
- [ ] 保存失败、外部指纹冲突及持续输入不能导致强制覆盖、无限重试或清空编辑器；既有重新加载与确认覆盖交互继续可用。
- [ ] 完整页面回归覆盖两种编辑器及切章、返回、搜索三类入口，验证文字与目的地；不得仅验证内部返回值或修改源函数隔离复现脚本。
- [ ] 已有自动保存、手动保存、指纹冲突和关窗约定的相关回归保持通过；不扩为关窗策略重设计。
- [ ] 提供可供切库流程复用的安全离开约定，说明完成、被阻止及陈旧请求的外部行为。
