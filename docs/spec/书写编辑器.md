## 一、定位与边界

- 书写板块＝**日常码字工具**：打开就能写、不丢字、知道写到哪。形态＝单章编辑器＋章节列表＋状态栏＋联动侧栏。
- 与拆书编辑器的关系：**手势一套，落点各走各的**。
  - 统一：Ctrl+Enter＝开下一章、Ctrl+S＝立即保存、粘贴图片自动入附件、保存穿同一道冲突闸。
  - 分岔：拆书的「下一章」＝同一文件里插章标题（一书一文件）；书写的「下一章」＝新建章文件并打开（一章一文件）。数据模型不同，强求同构反而别扭。
- 拆书专属（五插入块、桥段标注、AI 三命令）不进书写；书写专属（章节状态、字数口径与目标、联动侧栏）不进拆书。
- 共用底层：CM6 主题与基础扩展、原子写（`write_text_atomic`）、内容指纹保存闸（ADR 0004）。

## 二、章节管理

### 2.1 章节的表示（沿用 #4，不另立章节列表）

- 一章一文件：`正文/<NNNN 标题>.md`；NNNN 四位零填充、1 起；**序在文件名、标题可改、序不动**。
- 文件名解析：stem 匹配 `^(\d+)\s*(.*)$` → 序数＋标题。不合规文件（无数字前缀）仍列出（排在编号章之后、按名排序）、显示原名、序数留空、不参与自动编号；**应用不自动改名**（人的文件人负责）。
- frontmatter 只放**章节状态**（`状态: 草稿|完稿`），不放结构字段——序在文件名，这是 #4 的纪律。
- 章号显示由 `项目.yaml` 的「章前缀」渲染（`第7章 初入江湖`），缺省 `第{n}章`（单一事实源在 Rust 侧）。
- 章数/全书字数＝现扫 `正文/`（#12 无索引）；应用进入写作页时扫一次，之后按保存增量维护。

### 2.2 章节状态：草稿｜完稿

- 值集两态：**草稿｜完稿**（约定值只提示不校验，与词表同款纪律）；无 frontmatter 或没有「状态」键＝草稿。
- 存储：章节文件 frontmatter 的「状态」键；界面切换＝对编辑器缓冲做 **frontmatter upsert**（一次可撤销的事务），保留手补的未知键，不整块重写。
- 状态是给人看的进度标记，不参与任何自动流程（不因完稿而锁编辑、不因草稿而禁导出）。
- 第三态（修订中）v1 判死；复活信号＝用户真在两态之外手写别的值。

### 2.3 章节列表

- 平铺列表（v1 无卷，沿用 #4），按解析序数升序；每项＝章号＋标题＋状态徽章＋字数；当前章高亮。
- 点击切章：**先保存当前章**（冲突则中止并让人裁决），再载入目标章。
- 列表动作：
  - **新建**：序＝max(已有合规序数)+1，零填充四位；弹标题输入，**标题可空**（空标题文件名不带尾空格，列表显示「第N章（无标题）」）。
  - **重命名**：只改标题、序不动；目标文件名已存在则报错。
  - **删除**：确认后删文件（v1 不做回收站；纯文本＋快照可恢复）。
  - **重编号**：按当前序数顺序把合规文件重排为 1..N（修手删造成的空洞），逐个 rename，失败即中断报错。目标名互相占位（如 0002→0001 而 0001 还在）时先用点开头的临时名让路，扫描天然忽略临时名。
- 插入中间（补章）v1 判死；复活信号＝真需要回补旧章，届时＝新建＋后续重编号一条龙。
- 列表可折叠；「刷新」重扫目录（在 Obsidian 里加了文件后回来用）。

### 2.4 开下一章（Ctrl+Enter，与拆书同手势）

- 流程：**保存当前章**（冲突/失败则中止）→ 新建 max+1 → 打开新章（光标在正文首行）。
- 编号取 max+1 而非当前+1：中间有洞时不会撞号。
- 快捷键开章**不弹标题框**（码字零打断）：新章先无标题，标题可事后在列表里重命名；工具栏「新建章」按钮则弹标题框。
- 「空行回车自动开章」继续不做（设计共识 §四的留白）。

## 三、保存、冲突与快照

### 3.1 自动保存为主（用户拍板）

- 编辑器**停止输入约 3 秒**自动落盘；切章、开下一章、返回项目列表、离开书写板块时立即保存。
- 保存走 `save_chapter_md`（同一道指纹闸，ADR 0004）：载入时的指纹随保存带回，盘上不符＝冲突，**不写盘**。
- Ctrl+S 仍可用＝立即保存（不等防抖）。

### 3.2 冲突裁决（自动保存下的形态）

- 冲突时**不覆盖、不反复弹窗**：状态栏亮常驻横幅「本章已被外部修改」＋两个动作——
  - **重新加载**：放弃本地改动、重读盘上（二次确认）；
  - **确认覆盖**：带 force 重存（二次确认）。
- 冲突期间自动保存**暂停**（不再重试），本地改动仍在缓冲里；裁决后恢复自动保存。
- 不做文件监听/焦点刷新横幅（#12 纪律：保存闸是唯一卡点）。

### 3.3 快照与恢复（用户拍板：v1 做轻量快照＋恢复）

- 落点：`项目/《书名》/.gongbi/历史/<章文件名去扩展>/<YYYYMMDD-HHMMSSmmm>.md`（毫秒时间戳，同秒连存也保持字典序）。点开头目录，Obsidian 与全部扫描（`is_hidden`）天然忽略；随项目文件夹整体搬移，不丢。
- 触发：保存前，若盘上内容非空白、与**最近一份快照**不同、且距最近一份快照已满 **5 分钟**，先存一份快照（存的是「被覆盖的上一版」）。三条任一不满足就跳过——自动保存每几秒写盘一次，不节流会在十几分钟内耗光每章 200 份额度。
- 保留：每章最多 200 份，超出删最旧（个人工具够用；不引入压缩/增量）。
- 恢复：「历史版本」对话框——时间倒序列出当前章快照（时间＋字数），点选**只读预览**，「恢复」＝把该版本**载入编辑器**（未保存改动先二次确认），由自动保存/手动保存正常落盘——恢复本身不绕过冲突闸。
- 删除章**不删快照**：文件没了，快照还在盘上，可手动取回。
- 不做 diff 视图：对比交给 git／Obsidian 的 Version History 插件（与用户拍板一致）。
- 快照是纯文本副本，用户可脱离应用直接取用。

## 四、字数统计与目标

### 4.1 口径（两个数，各有用处）

- **计费字数**（主口径，网文口径）：去掉 frontmatter 块后，非空白字符数（含标点、含 markdown 标记）。对齐起点「计费标点计入、不含空格」的口径。
- **纯汉字数**（副口径）：Han 脚本字符数（Unicode Scripts.txt，含各扩展区、部首补充与 々/〇；天然不含标点/数字/字母/markdown 标记）。
- v1 不做 markdown 语法排除与「标准口径」（中文逐字＋英文按词）；复活信号＝用户发现计数与平台差得多。口径实现为**单一函数**（Rust 一份、前端镜像一份，同一套规则），全应用（书库/项目/章）共用，避免两套数。

### 4.2 显示

- 状态栏：`本章 3,214 字 · 汉字 2,890 · 全书 45,678 字 · 今日 1,200/2,000`；有选区时追加 `选中 123 字`。
- 章内计数实时（`docChanged` 防抖）；全书＝各章之和（进页扫一次＋保存增量维护）。
- 章节列表每项显示本章字数。

### 4.3 目标追踪（每日目标）

- 每日目标默认 2,000 字，可改（状态栏点击编辑）。
- **今日字数＝应用内净增量之和**：每次保存成功，`delta = 新字数 − 本次载入/上次保存时的字数`，累加进当天；跨天自动归零重开。
- 数据落**应用状态**（Tauri 应用数据目录 `书写/统计.json`：`{每日目标, 每日: {YYYY-MM-DD: 字数}}`），不进创作目录（R2 三层分离：创作数据/应用状态/可重建缓存）。
- 已知误差（接受并记录）：在 Obsidian 里当天写的字不计入今日；应用未打开时的外部改动不产生 delta。防跳变靠「每次载入以盘上字数为基准」，不引入时间戳校验。

## 五、写作体验

### 5.1 打字机滚动（v1，默认开）

- 光标行保持在视口中央；状态栏一键开关，偏好记忆（localStorage）。
- 实现：CM6 `scrollIntoView(pos, {y:'center'})`，选区变化时触发；不与输入抢焦点。

### 5.2 沉浸模式（v1）

- 一键进出：隐藏章节列表、联动侧栏与工具栏，正文居中固定列宽（约 40em），保留一条极简顶栏（章名＋退出）。Esc 退出。

### 5.3 行淡化（v1 可选，默认关）

- 非当前段落变暗、当前行高亮；状态栏一键开关，偏好记忆。默认关闭（用户拍板：可选功能）。

### 5.4 排版与布局

- 写作页三段：左章节列表（可折叠）｜中编辑器｜右侧栏（可折叠）；底部状态栏常驻。
- 正文排版：固定字号/行高/居中列宽（v1 不做设置面板）；主题沿用 `editorTheme`。
- 单章打开，不做多标签页；复活信号＝真频繁来回改两章。

## 六、联动侧栏

### 6.1 最小集（v1 全部来自 #4 的文件布局）

写第 N 章时右侧栏显示：

1. **本章所在单元**：按 `构思/单元/<名>.md` frontmatter 的 `起章/止章` 反查；显示单元名、核心矛盾、类型。
2. **该单元在排布中的位置**：第 k/N 个、线、地图、升级战斗、节奏（读 `排布.yaml`）。
3. **单元的「桥段安排」**（正文自由文本）：写这章时看「这一段要写什么」。
4. 未归入任何单元时：显示「本章未归入单元」＋怎么填（构思→单元里填起章/止章）。

### 6.2 单元↔章节的映射：单元 frontmatter 记单元区间

- `构思/单元/<名>.md` 新增**可选整数** `起章/止章`（懒填；只提示不校验重叠/越界——与 #4「按名引用只提示」同款纪律）。
- 这是对 #4 的落地细化（#4 已推荐「单元 frontmatter 记序数区间，与拆书桥段起/止同款」），不是翻案；单元文件是唯一存放处，不在 `排布.yaml` 重复。
- 填法：构思→单元的编辑表单里两个数字字段。

### 6.3 槽位与将来

- 侧栏按**区块**拼装，各区块自带数据来源；v1 只有「单元」区块。
- **#6 伏笔**：新增「本章伏笔」区块（埋设/待收列表），数据源由 #6 定；锚点方案不得污染正文结构（#6 已倾向正文零污染＋引文锚定）。
- **#7 三线**：新增「本章欠着的期待/目标」区块。
- 不渲染空区块（没有数据的区块不显示）。

- **#6 伏笔**：侧栏预留「本章伏笔」区块；正文是锚点面（一章一文件、可定位到章）。锚点持久化方案由 #6 定，但须守「正文零污染」倾向与 ADR 0002。
- **#7 三线**：侧栏预留区块；三线的线定义与 `项目.yaml` 情节线对齐由 #7 定。
- **#8 人物画布**：侧栏将来可加「本章出场人物」（出场人物块解析），等 #8/#11 的首行约定升格。
- **导出/发布格式**（地图雾区）：书写页不提供导出；发布前校对模式与之一并设计。本单决议后，该雾区项可毕业成新工单。

- **#12 索引与重建**：无索引现扫；保存闸是唯一卡点——本单自动保存不改这条，只是保存更频繁。
