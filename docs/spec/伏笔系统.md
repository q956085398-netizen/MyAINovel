# 伏笔系统 · 长期状态机 ＋ 写作中划选标注

> 工单 #6 决议。**代理最优解、用户未事前授权、可事后否决**——本单是 HITL 拷问工单，为在用户不在场时推进地图，按 #4 先例由代理给出最优解；否决即重开本单重议。
> 基线：ADR 0002（文件为唯一数据源）、ADR 0004（写路径原子＋读-合-写）、#2 调研（WNA 伏笔方案已从源码核实：**正文零污染 ＋ 引用定位 ＋ 四态状态机**，完全兼容 ADR 0002，可直接作为工笔伏笔模型基线）、#4（正文一章一文件、章序在文件名、锚点坐标＝章＋引文、伏笔数据落项目内）、#5（书写侧栏预留「本章伏笔」区块；锚点不得污染正文结构）、#11（渐进判据）、#13（结构化字段进 yaml、正文只放自由文本；约定值只提示不校验）。
> 用户原话需求：「既有长期的管理，也能在写作过程中选取文字右键设为伏笔，可以在本章节回收也可以在之后回收。」

## 一、定位与边界

- 伏笔＝**跨章节的长期线索对象**，带状态机。两个半区共用同一份数据：
  - **长期管理**（构思侧）：伏笔看板——按状态分组、超期统计（埋了 N 章未收的清单）。
  - **写作中标注**（书写侧）：选中正文右键「设为伏笔」/「回收伏笔」，本章侧栏看到本章伏笔，正文里锚点有装饰。
- **正文零污染**：不在正文插任何标记（不用 HTML 注释、不用自定义语法）。锚点＝「章序数 ＋ 引文」，存项目内的伏笔文件——正文在任何 md 工具里原样可读，Obsidian 手改不产生语法噪音。
- 不做：AI 伏笔建议、自动识别伏笔、跨书伏笔、伏笔与桥段/单元的自动关联。伏笔是人的判断，应用只做记录与提醒（ADR 0003 同款边界）。

## 二、数据：`项目/《书名》/伏笔.yaml`

- 落点：项目根下一个文件（**不是** #4 建议的 `伏笔/` 目录——单文件读-合-写与 `排布.yaml`/`词表.yaml` 同款纪律；伏笔名可含任意字符，一条一文件会撞文件名净化与改名问题；伏笔不被别的实体按名引用，不需要文件级身份）。
- 形态（中文键；**应用受管**，保存整表重写，条目内手补的未知键会丢——与桥段表同款分界）：

```yaml
- 名: 黄铜钥匙的下落
  状态: 已埋              # 待埋｜已埋｜部分收｜已收｜弃用（约定值只提示不校验）
  埋设:
  - 章: 1                 # 章序数（第几个章标题，1 起；与桥段起/止同一套坐标）
    引文: 他摸了摸口袋里那把黄铜钥匙，若有所思。
  回收:
  - 章: 12
    引文: 钥匙再次出现在酒馆的抽屉里。
    类型: 阶段            # 阶段｜终结
    说明: 揭露了主角的部分身世线索
```

- 字段：
  | 键 | 形态 | 必填 | 说明 |
  |---|---|---|---|
  | 名 | 字符串 | ✔ | 伏笔的身份；同名＝同一条（追加埋设/回收），不新建 |
  | 状态 | 字符串 | | 五态约定值；缺省按「待埋」显示 |
  | 埋设 | 列表 | | 每条＝`章`（序数）＋`引文`（选中原文） |
  | 回收 | 列表 | | 每条＝`章`＋`引文`＋`类型`（阶段｜终结）＋可选`说明` |
- **锚点为什么是序数＋引文**：序数对改名（应用「重命名」只改标题、序不动）与删章稳定，对任意章前缀模板成立（#13 同款理由）；引文定位章内位置，不存行号/偏移（编辑必漂移）。代价：整章重编号会挪动锚点、引文被改写会失配——两者都**只提示不自动改**（见下）。
- 未编号章节（文件名无数字前缀）不参与标注：右键标注时**当场提示先编号**（不打开弹窗），与「未编号文件不参与自动编号」同款纪律。
- 懒生成：文件不存在或为空＝还没有伏笔（与 `排布.yaml` 同款）；**解析失败时显式报错**（不覆盖、不静默重建）。

## 三、状态机与操作

- 五态：**待埋 → 已埋 → 部分收｜已收**；旁支 **弃用**（可恢复）。
  - 待埋：只有名字，还没写进正文（长期管理里先记下来）。
  - 已埋：有 ≥1 条埋设。
  - 部分收：有「阶段」回收、还没有「终结」回收。
  - 已收：有「终结」回收。
  - 弃用：人不打算收了；手改回其他值即恢复。
- 状态由应用在操作时维护、**显式存 yaml**（不派生自日志——手改 yaml 即生效，与词表/矛盾状态同款纪律）；应用不校验状态与日志的一致性（约定值只提示）。
- 操作：
  | 操作 | 入口 | 效果 |
  |---|---|---|
  | 设为伏笔 | 书写页选中文字右键 | 同名不存在→新建（状态=已埋）；已存在→追加埋设（待埋→已埋）；同（章,引文）重复标注不重复追加 |
  | 回收伏笔 | 书写页选中文字右键 | 追加回收记录（阶段/终结＋可选说明）；终结→已收，阶段→部分收（弃用不覆盖）；完全相同的一条（章,引文,类型,说明）不重复追加 |
  | 新建待埋 | 构思看板 | 只填名字；重名报错不合并（与单元同名同款，合并只发生在「从正文标注」时） |
  | 改状态 | 构思看板 | 五态任切（含弃用/恢复） |
  | 删除 | 构思看板 | 确认后整条删除 |

## 四、超期统计

- 对状态∈{已埋, 部分收}的伏笔：`未收章数 = 当前最大章序 − 最近一次埋设章序`。
- `未收章数 ≥ 20` 标**超期**（阈值＝约一个单元的篇幅，Rust 侧常量；复活信号＝用户想调，届时进项目.yaml）。
- 看板把已埋/部分收组按未收章数降序排，超期的置顶并标红；「待埋」单列一组。
- 只提示不拦截：超期不妨碍任何操作。

## 五、书写侧交互

- **右键菜单**（编辑器选区非空时）：「设为伏笔」「回收伏笔」。无选区不出菜单；未编号章当场提示先编号（见 §二）。标注弹窗的伏笔名预填选中文字前 12 字（可改）。
- **本章伏笔侧栏区块**（#5 §6.3 预留位）：本章埋设的伏笔（名/状态/引文）＋本章回收的伏笔（名/类型/引文）；点击条目在正文里选中并滚到引文处；引文在当前正文里找不到→标「引文失配」。没有数据时不渲染区块。
- **正文装饰**：当前章所有伏笔引文加下划线装饰（埋设＝虚线、回收＝实线），悬停显示「伏笔名 · 状态」；引文失配则不装饰。装饰随编辑自动重算（CM6 mark decoration），不写正文。
- **引文匹配规则**（Rust 与前端同一套，全应用共用）：先精确子串匹配；不中则去掉全部空白字符后再匹配（用于容忍换行/空格的差异）；仍不中＝失配，只提示、不改正文、不改锚点。
- 看板点「第 N 章」→ 跳到书写板块并打开该章、选中引文（跨板块跳转，与灵感库跳构思同款）。

## 六、构思侧看板

- 位置：构思项目页新增「伏笔」页签（与类型圈/矛盾/单元/排布/人物/世界观/开头并列），页签带条数徽标（与单元/矛盾同款）。
- 内容：按状态分组列表；每条显示 名、状态、埋设章/回收章摘要、未收章数（超期标红）、引文失配徽章。手写的不在五态内的状态值单列「其他状态」组（只提示不校验，改回五态即归组）。
- 动作：新建待埋、改状态、删除、点章跳转（见 §五）。
- 无伏笔时给一句引导（怎么写第一条）。

## 七、判死与复活信号

| 项 | 决议 | 复活信号 |
|---|---|---|
| 正文内嵌标记（HTML 注释/自定义语法） | 判死（正文零污染） | 引文失配频繁到不可用（届时议「序数＋起章标题双保险」而非内嵌标记） |
| 伏笔标签/搜索/筛选 | v1 不做 | 伏笔多到看板翻不动（几十条以上） |
| 时间戳（埋设/回收时间） | v1 不做（章序数已能排序） | 想按真实日期回看 |
| 超期阈值可配 | v1 固定 20 章 | 用户想调 |
| AI 伏笔建议/自动识别 | 判死（ADR 0003） | — |
| 伏笔↔单元/桥段自动关联 | v1 不做 | 真需要按单元看伏笔 |
