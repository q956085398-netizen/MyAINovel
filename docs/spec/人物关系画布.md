# 人物关系画布

> **2026-09-19 后续裁决（优先级最高）**：本页旧版关于「人物单一分组」「仅人物节点」「不可拖拽、坐标不落盘」以及 `构思/人物关系.yaml` 的决定已被替代。新版画布同时呈现人物与一等组织；人物可属于多个组织；人物节点为圆形、组织节点为方形或圆角方形；节点可手动拖拽并持久化，可钉住；提供「整理画布」和可撤销的「全部重排」。社会关系与布局统一存入 `构思/关系.yaml`。下文保留为历史背景；实现以 [产品设计补遗](../产品设计补遗.md)、[ADR 0008](../adr/0008-first-class-maps-regions-and-social-graphs.md) 及本段为准。

> 卡片与画布是同一份实体数据的两种视图：人物卡采用结构字段与自由正文混合，组织卡完整展示；画布不得另存人物或组织副本。

> 工单 #8 决议（**grilling：两轮问答由用户逐项拍板**）。基线：ADR 0002（文件为唯一数据源）、ADR 0004（写路径）、#4（构思数据模型与文件布局）、#2（调研 §6.3：模型抄 Campfire、落地抄 WNA）、#9（转生接口形态）。
> 定位：方法论「人设」节的落地——人物小传（生平＋找感觉的图片）→ 按阵营分组 → 连线标关系（敌对/师徒/私情/亲戚/未解之谜）。「人物之间有足够关联，人物又意味着一个又一个的剧情」——**关系网本质是剧情发生器**。

## 一、决议总览

| 问题 | 决议 |
|---|---|
| 边怎么文件化 | **单文件边表** `构思/人物关系.yaml`（图例＋边表同住），人物文件只管小传 |
| 坐标与交互 | **确定性自动布局**（按分组分簇），不可拖拽、坐标不落盘 |
| 角色卡转生 | **对称 #9**：标题→人名、卡片正文→小传正文，其余留卡片，单向关联、转生即断链 |
| 从画布到剧情 | **三件都做**：选中数人「提为矛盾」＋ 人物交汇只读视图 ＋ AI 命令「人物关系梳理」 |
| 图例起步 | **预置四类种子**（师徒有向／敌对无向／私情无向／亲戚无向），可增删改 |
| 交汇视图口径 | 边 ＋ **共同出现的单元**（扫 `构思/单元/*.md` 正文的人名提及） |
| AI 命令材料 | 小传＋相关边＋项目类型圈＋矛盾池现有标题 |
| 「提为矛盾」预填 | 人名＋他们之间的边（**不写分析结论**） |

## 二、关系网文件：`构思/人物关系.yaml`

### 形状

```yaml
图例:
  - 名: 师徒
    色: "#c0392b"
    方向: 有向
  - 名: 敌对
    色: "#7f8c8d"
    方向: 无向
关系:
  - 起: 张三
    止: 李四
    类型: 师徒
    描述: 张三收李四为徒，实为监视
    秘密: true
  - 起: 张三
    止: 王五
    类型: 敌对
```

- **图例**＝画布级的「可命名、有序、可绑定方向的分类集合」（Campfire Relationship Key 的工笔版）。顺序即图例面板的显示顺序与自动配色次序。`方向` 只有 `有向 | 无向` 两个值，认不出/缺省一律**按「无向」读**——约定值，不为一个手滑值把整张网判成读不懂。
- **边表**字段：`起`/`止`（人名，按名引用 `构思/人物/<人名>.md`）、`类型`（按名引用图例项）、`描述`（可选自由文本，可多行）、`秘密`（可选布尔，缺省否，只写 `true`；写别的＝格式坏了，**显式报错**——秘密标记静默翻成 false 是语义丢失，不是显示默认）。
- **方向是图例项的属性，不是边的属性**：师徒有向、亲戚无向——边继承它，不逐条设。
- **同一对人可有多条边**（师徒＋私情并存），列表项无唯一性约束。
- **无向边只写一条**：无向边画一条无箭头线，不要求写两条。
- `起→止` 只表示**有向边的方向**，不是「谁拥有这条边」——关系网是一张网，不属于任何一方；因此反向关系由应用现算，**没有镜像副本，也就没有一致性问题**。

### 为什么是单文件边表

- 方法论里的「关系网」是**一张网**（纸上在人名之间连线），不是某人的属性；一个文件装整张网，语义对齐。
- 与 #4 的 `排布.yaml` 同一范式（按名引用＋读-合-写＋只提示不校验），复用既有纪律与代码模式，不新造范式。
- 图例是画布级的东西，与边同住一个文件才不会跨文件失联。
- 代价：在 Obsidian 里打开某个人物文件看不到他的关系，要开关系文件。人物文件正文里的自由文本不受限制，人想写一句关系备注随时可写。

### 住在哪、懒生成、写路径

- 位置：`项目/《书名》/构思/人物关系.yaml`（与 `排布.yaml` 同目录，同属「构思」）。
- **懒生成**：文件不存在时应用用「缺省图例＋空边表」内存默认值渲染（缺省图例＝四类种子，单一事实源在 Rust 侧 `DEFAULT_LEGEND`）；**首次连边或人主动改图例时才落盘**，落盘内容＝当时的图例＋边表。与 #4「项目.yaml 懒生成」、#10「词表首用落盘、此后只读」同一条纪律。
- 读-合-写、原子写（ADR 0004）。未知键分两层：**顶层**未知键原样保留（与 `项目.yaml` 同款）；**条目内**不认的键整表重写会丢（应用受管，与 `伏笔.yaml`/拆书 yaml 同一条纪律）。
- 文件损坏：不拖垮画布——降级为「缺省图例＋空边表」并**显式告警**（与 #4「单文件损坏」同款）。**并且拒绝覆盖**：降级态下写盘一律报错停用（与 #10 的「损坏词表报错且不覆盖」同款）——画布此时显示的是空表，照常保存会把用户手写的整张网换成空表。

### 引用失效：只提示不校验

| 情况 | 处理 |
|---|---|
| 边引用的人物名在 `构思/人物/` 下不存在 | 画不出这条边，在画布下方列「失效引用」；删改留给人 |
| 边引用的类型不在图例里（或图例项被删） | 边照画，用缺省样式（主题灰、有向），列「图例外的类型」；**不回写、不清理** |
| 同一对人重复写同类型边 | 照画（列表项无唯一性）；不自动去重 |

与「排布→单元」「排布属性→情节线/地图」的失效纪律同款：**只提示，删改留给人**。

## 三、画布形态：确定性自动布局

### 布局是不落盘的纯函数

- **不可拖拽、坐标不落盘**：布局＝读边表＋人物分组现算（#12 无索引纪律），每次打开一样。
- 规则：按人物 frontmatter 的 `分组` 分簇 → 各簇纵向铺开、簇内**环形**排布（节点按人名稳定排序，避免抖动）。无 `分组` 的人物归一簇「未分组」，排在最后；分组的颜色按簇序取自色板，节点描边与簇名同色（一眼看出阵营）。
- 为什么不做坐标持久化：调研 §2.4/§6.3 把「自由画布坐标的持久化」点名为 md 方案的最大难点（Campfire 闭源无从参考）。坐标进创作数据＝每次拖动的 diff 污染文件；进应用状态＝要维护人物改名/删除后的孤儿坐标。几十人规模下确定性布局够用。
- **复活信号**：真出现「看不清谁和谁」→ 加拖拽，坐标进**应用状态**（不进创作数据），丢失回自动布局。

### 节点与边

- **节点＝人物文件的引用视图**（不复制数据，Campfire 同款）：显示人名＋分组色；**单击切换选中**（可多选，用不着按修饰键——多选是这个画布的主要动作），侧栏列为选中的每个人给出小传预览、他的边（点一条即可改）与「小传」编辑入口。
- **边**：颜色与线型取自图例项；有向画箭头，无向不画。线中点显示类型名。
- **秘密边**：虚线＋中点类型名带「？」（方法论「某两个人物之间有一些没有解开的秘密」）。秘密是**可叠加在任何类型上的布尔标记**，不是图例里的一种类型——师徒之间也可以有未解的秘密。
- 画布只画不写人物文件。

### 与「自动提及关系」的边界

v1 只画**显式边**。WNA 的「自动提及关系」虚线层（正文里两人名字同时出现就画虚线）**判死**：要扫正文、人名匹配误报多，且与拆书侧「谁出场」统计成第二个口径。复活信号：人反复问「这两个人有没有一起出现过」。

## 四、UI 落点

- **入口：「人物」页签内的视图切换（名单 ｜ 画布）**，不新增页签——人物与关系是同一件事的两面，两个页签会互相竞争注意力。
- 名单＝现有的 `NoteList`；画布＝新增 `RelationshipCanvas`。
- 画布工具条：图例面板（增删改：名/色/方向，顺序即列表顺序）｜「连一条关系」（对话框：起/止下拉选人物，或先选中两个节点）｜「提为矛盾」（选中 ≥2 人可用）｜「交汇」（选中 ≥2 人可用）｜「AI 梳理」（选中 ≥2 人可用）。
- 画布下方：失效引用与图例外的类型提示（只提示，见第二节）。

## 五、角色卡 → 书内人物（转生）

对称 #9 的故事卡转生：

| 人物字段 | 来源 |
|---|---|
| 人名 | 卡片标题（净化后，与单元同一套命名纪律） |
| 小传正文 | 卡片正文 |
| 分组／别名 | 留空 |

- 卡片字段没进人物的（标签/来源/关联）留在卡片——**卡片是种子，人物是新生命**。
- 卡片「关联」追加一条 `《书名》/人名`（已存在则不重复）；**单向、按名、无同步、转生即断链**（#9 纪律原样）。
- 同名人物已存在 → **报错让人裁决**（与「矛盾提为单元」同款），不自动续号。
- 转生必须选书（复用 #9 的选书对话框）；没有项目时引导去「构思」板块新建。
- **转生不生关系**：分组留空、边表不动——连线是画布上的事，转生只管把人带进屋。

### 关联解析的扩展（#9 遗留尾巴）

#9 定的解析是「含 `/` 的条目按 `《书名》/单元名` 打开该项目的单元页」。本单扩展为固定次序的四步：

1. 先按**单元名**找（#9 原样，保持既有卡片不失联）→ 打开「单元」页签；
2. 找不到再按**人物名**找 → 打开「人物」页签的**画布视图并选中该节点**；
3. 再找不到按矛盾／世界观／开头名找 → 打开对应页签；
4. 项目对得上但名字一个都不中（单元改了名之类）→ 按 #9 兜底打开该项目的「单元」页；**不自动改条目**（引用失效只提示，删改留给人）。

不引入新的编码格式（不在关联里写类别前缀）：同名歧义由「先单元后人物」的固定次序裁决，且同名本身是设计上要避免的（#4「按名引用」纪律）。

## 六、从画布到剧情

三件事都做，边界一致：**不生成剧情内容**（ADR 0003），只预填已有字段——与「故事卡转生」「矛盾提为单元」同一形态。

### 6.1 选中数人 →「提为矛盾」

- 选中 ≥2 个节点 → 建 `构思/矛盾/<名>.md`：
  - **标题**：对话框里人填，预填一个串人名的建议名（如 `张三·李四`）；
  - **正文**：空骨架 ＋ 一行「涉及人物：张三（师徒→李四·秘密）、王五」——每条边挂在它的「起」名下（无向边用「－」），**只写选中集内的边**（选中集之外的邻居不拉进来，那会变成一份没人认领的名单）。
  - **frontmatter**：`状态: 池中`，其余留空（类型由人后续填——词表只提示不校验）。
- **不写分析结论**（不写「能撑起什么」「爽点在哪」）：矛盾是种子，边是「这几个人为什么能凑出剧情」的最小依据；分析结论会变成要维护的欠账。
- 同名矛盾已存在 → 报错让人裁决。
- 不改边表、不建单元——提级链路保持单向：**人物 →（人拍板）→ 矛盾 →（人拍板）→ 单元**。

### 6.2 人物交汇（只读视图）

- 选中 ≥2 人 → 交汇面板给两样：
  1. **他们之间的边**（含类型/描述/秘密）；
  2. **共同出现的单元**：扫 `构思/单元/*.md` 正文里的人名提及（零结构，不新增字段）。
- **不扫正文**：正文几十万字每次现扫（#12 无索引纪律下代价真实），且人名匹配误报多（同名、昵称、提一嘴不算出场）；「谁出场」这类统计拆书侧已有，构思侧再扫会成第二个口径。
- 「共同单元」是**人名的纯文本提及**，不区分主次——只给人看，不做自动判断。

### 6.3 AI 命令「人物关系梳理」（#15 第 5 条命令）

- **材料**（后端 `ai_context.rs` 现读组装，提示词仍在前端）：选中人物的小传（正文＋分组/别名）＋ 他们相关的**全部边**（含不在选中集里的邻居人名）＋ 项目**类型圈** ＋ **关系图例**（这本书的关系词汇：有哪些类型、哪个有向）＋ **矛盾池现有标题**。
- **只出报告，不写创作文件**（#15 纪律）；材料上限入 Rust 可测、缺数据显式占位、线索表坏了显式报错。
- 为什么带类型圈与矛盾标题：类型圈是判断「这条关系能不能长出圈内剧情」的唯一依据；矛盾池标题是防重复的唯一依据。**不塞全书人物名单**——与「选中几个人」的动作意图冲突。
- 入口：画布工具条的「AI 梳理」（选中 ≥2 人可用），走现有 AI 侧边栏命令机制。

## 七、判死与复活信号

| 判死 | 复活信号 |
|---|---|
| 画布坐标持久化／可拖拽 | 真觉得「看不清谁和谁」 |

| 人物文件里存关系 | —（本单已定：边只在边表） |
| 关系网与拆书「出场人物」联动 | —（#4 已定：拆书数据不读） |
