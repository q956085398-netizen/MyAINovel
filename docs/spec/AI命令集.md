# AI 命令集 · 构思与书写板块

> 工单 #15 决议（**代理最优解、用户未事前授权、可事后否决**——否决即重开本单重议）。
> 基线：ADR 0003（AI 只处理人写的内容；给初稿/建议，人确认后才落盘）、设计共识 §七（侧边栏对话＋编辑器命令）、#5 书写编辑器、#6 伏笔、#7 三线、#14 导出与发布（AI 润色/一致性检查留在此处复活）、ADR 0002（文件是唯一数据源）。
> 本文件定「构思/书写板块的 AI 命令」：命令清单、材料口径、回写纪律、落点。

## 一、定位与边界

- **AI 还是助手**：命令＝把「人已经写下的内容」按一个用途整理成材料，交 AI 出判断/初稿；人不采纳，什么都不会变。
- **命令＝四条**：构思侧 `排布体检`、`矛盾梳理`；书写侧 `本章体检`、`润色`。与拆书编辑器三条（`梳理`/`标注`/`小结`）同一套种子—提示词—采纳管线。
- **材料从盘上现读**（ADR 0002）：命令的上下文由后端按固定口径组装成一段纯文本，不从界面状态里抠——界面可能落后于盘（Obsidian 在手改），且口径要可测。
- **不写创作文件的命令就是只读命令**：三条体检类命令只出报告，不下结论到文件；`润色` 是唯一带回写的命令，落盘走「点采纳」这一步。
- 不做：AI 直接写/改任何创作文件、自动重排排布、自动改写正文（无采纳闸的写回一律判死）；命令之间互相串（体检不自动接着润色）。

## 二、四条命令

### 2.1 排布体检（构思 · 排布页签）

- **问题**：这份大纲（次序＋升级:战斗＋张弛＋地图）读起来有没有结构问题。
- **材料**：书名、类型圈的类型清单、排布全表（次序、单元名、线/地图/升级战斗/节奏、每单元一句话核心）、机检提示（`check_project_arrangement` 的输出：比例、连续同调、按名引用失效、未排布的单元、地图分布——材料与排布页共用同一个落地函数，不另写一份）。
- **输出纪律**（提示词）：结构判断 → 点名到具体位次的风险点 → 最多 3 条调整建议（说清动哪一项往哪动）；材料不足直说，不编造没给的单元。
- **跑之前先落盘**：排布页有未保存改动时先保存再跑（材料读的是盘上的排布，别让 AI 看旧稿）。
- **只出报告**：不改 `排布.yaml`；要动排布是人在排布页上动手。

### 2.2 矛盾梳理（构思 · 矛盾页签）

- **问题**：这一池矛盾种子，哪些能长成单元、哪些重了、哪些偏了。
- **材料**：书名、类型圈、已有单元名清单、矛盾池全表（名、状态、类型、一句话核心；核心缺失时取正文开头 60 字并标「正文摘」）。
- **输出纪律**：分四组——可展开成单元的（附一句展开方向）／彼此或与已有单元重复的／偏离类型圈的／信息不足的；点名到具体矛盾，每条两行内；不替用户写剧情正文。
- **只出报告**：不建单元、不改矛盾（要展开走既有的「提为单元」）。

### 2.3 本章体检（书写 · 写作页）

- **问题**：这一章本身怎么样、欠了什么账。
- **材料**：书名、本章（章序＋标题）、所属单元（单元区间反查 `find_unit_for_chapter` 的产物：核心、区间、排布位次与属性）、本章伏笔（锚点或回收落在本章的）、本章三线（同款）、全书未收的线（已埋/部分兑现的线，超期与拖得久的在前，最多 30 条，带未推进章数与超期标记）、本章正文。
- **输出纪律**：① 章节拍对照（代入/信息差/拉扯/兑现/善后/启下：哪些在、哪些缺、哪个过头，要引正文证据）；② 欠账提醒（该埋没埋、该收没收的伏笔与期待线，点名；拖太久的线点出来）；③ 最多 3 条可改进点，指到具体位置。只依据给的材料，不补设定、不猜后续。
- **只出报告**：不改正文；要改是人在编辑器里改。
- **跑之前先落盘**：正文有未保存修改时先存一次（体检读的是盘上的正文），保存冲突未解决就不跑。

### 2.4 润色（书写 · 写作页，需选中正文）

- **问题**：选中的这一段，字句能不能更好。
- **材料**：选中的正文（＋一句「第 N 章 标题」的抬头）。
- **输出纪律**：只改字句（用词、节奏、语气一致），不改人称视角、不增删情节与信息；**直接输出润色后的正文**，不要解释、不要标题、不要代码栏；拿不准的地方保持原样。
- **唯一带回写**：采纳＝`替换选中`（ADR 0003 的「人确认后才落盘」——不点按钮不落盘）。替换前只做两件事：去掉多余的包裹代码栏、去首尾空白；**不压空行、不动分段**（正文字该是什么样是人的事）。替换后走正常自动保存与快照，`Ctrl+Z` 可撤销。选区已消失或为空时采纳按钮只报「编辑器不可用」，不做无选区插入；不在书写板块时同样不认（三个板块常驻挂载，写作页切走后还在，不许悄悄改到看不见的正文）。

## 三、材料口径（后端固定组装）

- IPC `build_ai_context(kind, project, chapter?)` 返回一段带小节标题的纯文本；提示词在前端（`ai.ts`），材料在后端——两处各管一段，互不重复。
- 材料小节用 `【名】` 抬头，缺数据给显式占位（`（类型圈还没定）`、`（排布还是空的）`、`（矛盾池是空的）`、`（本章还是空的）`），**不留空小节**——AI 才知道「没有」和「没给」的区别。
- 上限与截断（常量入 Rust、可测）：
  - 本章正文 12000 字（超出截断并在材料里注明「正文已截断」）；正文小节用成对的 `--- 正文开始 ---` / `--- 正文结束 ---` 包裹（空章也成对）。
  - 引文预览 30 字、一句话核心 80 字（超出带省略号）、矛盾正文摘 60 字；都折叠为单行（连续空白压成一个空格）。
  - 全书未收的线最多 30 条（超出注明「只列前 30」；超期与拖得久的在前）。
- 读不动的材料**显式报错**（沿用扫描纪律）：类型圈/排布/矛盾池/伏笔/三线解析失败 → 命令报错、不发出请求；机检提示是纯函数派生，不额外读盘。
- 材料进会话：命令的用户消息就是这份材料（带 `meta.kind`），会话里能回看「AI 当时看到的是什么」。

## 四、落点与侧边栏

- **按钮长在板块里**：构思项目页的排布页签与矛盾页签各一个（pane 头部，挨着「保存」/「新建」）；写作页顶栏两个（`AI 体检`、`AI 润色`，无章节/无选区时置灰）。沿用拆书编辑器「AI 命令」的既有形态，不新造入口。
- **侧边栏扩三处**：
  - `AiSeed` 放宽：行号可选（体检类命令没有行号），新增 `润色` 的采纳动作 `替换选中`。
  - `MessageMeta` 同步放宽；报告类命令没有采纳动作（报告不落盘）。
  - 「携带当前文档」按板块取：拆书＝当前拆书稿，书写＝当前章（项目名＋章名当抬头）；构思板没有「当前文档」，勾选框置灰。
- **空态文案**改成四板块通述：拆书三条命令、构思两条、书写两条，一句话说清「AI 只给初稿与建议，采纳后才会写入」。
- App 持有两个桥：拆书编辑器的桥（`getDoc`/`adoptCallout`/`adoptTrope`）与写作页的桥（`getDoc`/`replaceSelection`），按当前板块取用。

## 五、判死与复活信号

| 项 | 决议 | 复活信号 |
|---|---|---|
| AI 直接改创作文件（无采纳闸） | 判死（ADR 0003：人确认后才落盘） | 无——纪律不是偏好 |
| 排布自动重排 / 自动生成单元 | 判死（AI 给建议，顺序是人的判断） | 无——同上 |
| 人物卡/世界观一致性检查 | v1 判死（「角色」实体要等人物关系画布 #8 定稿） | #8 落地后另开单 |
| 单元/人物/世界观等其余卡类的梳理命令 | v1 判死（先看矛盾梳理用不用） | 用户反复手搓同类提问 |
| 批量润色整章/全书 | 判死（润色是逐段判断，不是流水线） | 真出现「整章过一遍」的稳定用法 |
| 体检报告里的行号跳回 | 判死（AI 输出的行号不可靠解析，会误导） | 用户抱怨找不着位置 |
| 整章自动摘要 | 判死（ADR 0003 已锁） | 无 |
