# 写路径规范：原子落盘＋长活缓冲带版本指纹

所有落盘写必须走「同目录临时文件＋rename」原子替换（防半截文件，Obsidian/git 读到写一半的文件）；**长活缓冲**（应用内存里长期持有、由人编辑的内容，如拆书正文、将来的书写正文）在整文件覆盖保存时必须携带版本指纹做乐观锁——盘上内容与载入时不符即拒绝写入、交人裁决（重新加载或确认覆盖），不允许后写静默赢。

版本指纹取**内容指纹**（字节数混入的 64 位哈希），不用 mtime：不受文件系统时间粒度、touch/复制影响，且可测试。读文件时返回指纹，保存成功返回新指纹供下一次携带。

「读-合-写」路径（保存瞬间重读盘上文件为底、合并保留未知键——书级资料、桥段列表、灵感卡 frontmatter）视为已满足冲突安全：外部改动保留在未知键里，破坏面缩小到「同键不同值」的真人冲突，v1 不设闸。

## Considered Options

- **后写赢（无任何防护，否决）**：Obsidian 是同一库的第二个客户端，静默覆盖＝静默丢数据，违背 ADR 0002「文件为唯一数据源」的信任基础。
- **mtime 乐观锁（否决）**：Windows 上粒度尚可，但 touch/复制/同步盘会误报，且等值比较不可移植；内容指纹同成本下更真。
- **文件锁（否决）**：要求 Obsidian 配合，不现实；纯个人工具也不需要互斥，只需要「覆盖前对账」。

## Consequences

每个将来的写路径（构思板块、书写编辑器）立项时就要选边：长活缓冲必须穿指纹，读-合-写必须保留未知键；代价是每次保存多读一次盘上文件算哈希（个人库规模无感）。修订 ADR 0002 的留白：「文件写入需保证原子性，避免与 Obsidian 同时编辑时互相覆盖」自本 ADR 起为硬规范。
