# 故事卡转生单元草稿接口

> 工单 #9 决议（用户已授权代理给最优解，事后否决即可）。
> 依赖已就位：#4（单元落点 `构思/单元/`、核心矛盾/类型字段、按名引用纪律）、#10（词表只提示不校验）、#11（渐进判据：不预先埋结构）、#13（不设硬引用）。
> 定位：设计共识 §六「故事卡可一键转生为单元草稿」——拆书→灵感→构思链路的最后一环。

## 决议

### 转生产物：空骨架 ＋ 预填卡片已有字段

- 产物 = `项目/《书名》/构思/单元/<卡片标题>.md`：

  | 单元字段 | 来源 |
  |---|---|
  | 单元名 | 卡片标题（净化后；与「矛盾提为单元」同一套命名纪律） |
  | 核心矛盾 | 卡片「一句话核心」 |
  | 类型 | 卡片「标签」（自由字符串，可能不在词表里——只提示不校验） |
  | 正文 | 与「矛盾提为单元」同一份骨架：`## 桥段安排` ＋ 一个空序号 |

- **不生成内容**：不做「人物＋困境＋爽点预期」三栏拆解、不预填 4~5 个桥段、不给章节拍提示。理由：
  1. 把一句话核心拆成三栏＝生成内容，踩 ADR 0003 的边界（AI 只处理人写的内容）。将来若要，正确形态是「AI 建议 → 人确认」的编辑器命令，不是转生自带的魔法。
  2. 章节拍 v1 判死（#11）；4~5 个桥段占位是「预先埋结构」，与「桥段清单写在正文、自由文本」（#4）冲突。
  3. 骨架只有一种形状（单一事实源在 Rust 侧 `UNIT_TEMPLATE`），两条提级路径（矛盾→单元、故事卡→单元）产物一致，人不用分辨东西从哪来。
- 卡片字段没进单元的：来源/关联/正文留在卡片——**卡片是种子，单元是新生命**。

### 落点：用户选目标项目

- 转生必须选书：对话框列出 `项目/` 下全部项目（按书名），默认选中第一个；没有项目时引导去「构思」板块新建（转生不长出第二套新建项目流程）。
- 同名单元已存在 → **报错让人裁决**（与「矛盾提为单元」同款），不自动续号：单元是排布按名引用的实体，静默续号会让排布引用错对象。

### 关联：卡片侧「关联」单向记去向，无同步

- 转生成功后，卡片「关联」追加一条 `《书名》/单元名`（已存在则不重复）。
- 方向单向（卡片 → 单元）、按名不设硬 id：卡片或单元改名都不会自动改对方（#4 纪律「不设硬引用，避免改名失联」）。
- 「改卡片要不要同步」：**不同步，转生即断链**——单元的核心矛盾只是转生那一刻的抄本。同步＝双写，谁覆盖谁没有答案；且卡片可转生到多本书，多目标同步更无从谈起。
- 灵感库「关联」的解析加一条约定：含 `/` 的条目按 `《书名》/单元名` 解析，打开该项目的「单元」页；书名对不上时按现有兜底提示「没找到」，不自动改条目（引用失效只提示，删改留给人）。

### 批量：v1 单卡转生

- 一次一张卡。灵感库是全局素材池，卡片之间没有次序语义；批量转生＝替人做「哪些种子先长」的决策，而排布是构思期决策（#4 只提供派生体检）。
- 复活信号：用户反复一次转十张 → 再议「整池转生」，届时形态大概率是「多选 → 选书 → 逐张落单元（**不自动排布**）」。

### 其他卡类：v1 不做

- 只做故事卡→单元（设计共识 §六只写了这一条）。角色卡→人物、世界观卡→世界观词条的**落点**已在 #4 定，但字段映射依赖 #8（人物实体与关系）与词条字段的最终形态，留到 #8 一并定。

## 实现纪要（v1 落地）

- Rust：`project::transmute_story_card(root, card_path, project)`；`inspiration::read_card` / `inspiration::append_link` 公开。写入次序＝**先记卡片去向、再建单元**：建单元失败只留一条失效软链，重试即自愈（同名检查在写之前，重试不会被同名挡住）；反过来会在失败时留下无人记账的单元。
- 前端：灵感库故事卡条目「转生为单元」按钮 ＋ 选书对话框；转生成功刷新卡片列表并跳到该项目「单元」页。
