# 索引与重建

> 工单 #12 决议（用户已授权代理给最优解，事后否决即可）。回应 ADR 0002 的留白：「跨书类型/解法检索的质量取决于索引的重建策略；文件写入需保证原子性，避免与 Obsidian 同时编辑时互相覆盖」。
> 写路径规范（原子写＋冲突闸）升级为 ADR-0004，本文件只记拆书链路的落地面。

## 决议

### 索引：v1 无索引，现场扫盘即「索引」

- 书库浏览、全文搜索、词表聚合每次进入都**现扫盘**（现状即是）：个人库规模（百来本、几十 MB）全扫毫秒级，换来的是**永不过期**——Obsidian 里改完，回到应用下一次进入即天然可见，无失效逻辑、无重建入口、无脏缓存。
- 「重建策略」在无索引下是个不存在的问题，这正是 v1 选它的理由：**不引入自己修不好的东西**。
- **引入缓存的触发线**（满足任一再说）：全库扫描出现可感知卡顿（约 >1s）；搜索需要打分排序/正则加速；库规模超过约百本。届时形态预定为 SQLite（或内存态启动构建），仍守 ADR 0002「可弃缓存」。

### 将来缓存的重建纪律（引入时照此执行，现在只立规矩不写码）

- **触发**：启动时全量扫建缓存；运行中 `notify` 监听库目录做增量**失效标记**（只标脏不搬数据），读时发现脏即回源文件。
- **重建**：缓存头带 schema 版本号，版本不符、启动校验失败、用户手动——三种情况整弃重建。因为缓存可弃，重建不做进度呈现，前台直接重扫（个人库规模）。
- **自愈铁律**：任何缓存与文件不一致，一律以文件为准；缓存损坏不抢救，删了重建。应用永远不因为「缓存里有」而拒绝读文件。

### 写入（v1 落地部分）

- **原子写**：既有规范——同目录 `.gongbi.tmp`＋rename（Windows 的 rename 带 REPLACE_EXISTING），正文/yaml/词表/灵感卡全走它。
- **正文保存冲突闸（本次落地）**：正文是长活缓冲（编辑器打开期间人一直在改），按 ADR-0004 必须带版本指纹：
  - `read_book_md` 返回 `{内容, 指纹}`，指纹＝内容指纹（字节数混入的 64 位哈希）；
  - `save_book_md` 携带载入时的指纹：盘上指纹不符（Obsidian 在这期间保存过）→ 返回 `conflict`，**不写盘**；前端亮明冲突，给人两条路——「重新加载」（放弃本地改动，重读盘上）或「确认覆盖」（带 force 重存）；
  - 保存成功返回新指纹，前端更新记忆，连续 Ctrl+S 不误报；
  - 载入时文件不存在、保存时已出现（别人创建了同名文件）同样判冲突。
- **yaml 侧不设闸**：书级资料、桥段列表是「读-合-写」——保存瞬间以盘上文件为底合并、未知键保留（ADR-0004 视为已满足），外部改动的存活面不依赖闸。

### 编辑器内读到旧内容的兜底

编辑器缓冲在 Obsidian 保存后会变旧——v1 不做 watch/焦点刷新横幅（提示噪音大于收益），**保存闸是唯一卡点**：只要不保存就不会互相覆盖；真保存时必被拦下对账。显示层旧一点无害，数据层不失真。

## 对其他工单的影响

- **#13（yaml schema）**：懒生成不变——无索引意味着「先入索引后落盘」的说法收窄为「yaml 文件本身懒生成」，跨书检索永远是现扫，不依赖 yaml 是否存在。
- **v1 代码**：`read_book_md`/`save_book_md` 签名升级（指纹进出＋`SaveResult`），`EditorPage` 存指纹、处理 `conflict`（重新加载/确认覆盖二选一）。
