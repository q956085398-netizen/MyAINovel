# 文件为唯一数据源，索引只是缓存

所有数据（拆书稿、灵感卡、书库元数据）以纯文本文件（Markdown + YAML + 附件图片）存放在用户自选的文件夹中；应用维护的索引（如 SQLite）只是可随时删除、重建的缓存。库文件夹可以直接指向现有的 Obsidian vault 子目录（如 `写作学习/拆书分析/`），应用识别现有布局（根目录散文件或一书一文件夹均可），不强制搬动、不改写用户文件结构。

## Considered Options

- **数据库为主存储**（MuMuAINovel 的做法，否决）：检索能力强，但用户不拥有明文数据、无法用 git 做版本管理、换工具即被锁定。
- **纯文件 + 每次实时解析**（否决）：跨书桥段检索在书库变大后会慢。

## Consequences

跨书"类型/解法"检索的质量取决于索引的重建策略；文件写入需保证原子性，避免与 Obsidian 等外部编辑器同时编辑时互相覆盖。
