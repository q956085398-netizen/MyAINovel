# 启动与分发

> 工单 #34 决议（2026-09-13 访谈拍板）。基线：设计共识 §一（Windows 优先、纯个人使用）、`tauri.conf.json`（bundle targets＝all；release 已无控制台窗口——`main.rs` 的 `windows_subsystem` 属性）。
> 起因：用户不想每次敲 `npm run tauri dev`（还带终端窗口），也不想每升级一次就重新打包。

## 一、决议

- **双轨**：
  1. **无终端 dev 启动器（日常）**：双击脚本隐藏控制台跑 `npm run tauri dev`——代码总是最新，代价是冷启动要等增量编译（数秒~数十秒，首次更久）。
  2. **构建产物（备份）**：`npm run tauri build` 一次性产出 NSIS 安装包＋MSI＋独立 exe，作备份/重装用；它们是代码快照，升级需重新构建。
- **启动器**：仓库根 `启动工笔.vbs`（隐藏窗口、工作目录切 `app/`）；配套说明如何在桌面建快捷方式（`建桌面快捷方式.vbs` 一键建）。「正在启动…」提示窗为定时自动消失（20 秒），不轮询应用窗口——VBS 的 Popup 无法被外部关闭，轮询得不偿失。
- **启动防顶死**：`npm run dev` 挂 `predev` 钩子（`app/scripts/free-port.cjs`）——起 vite 前查 1420 口，被残留的 node（上次没退干净的 vite）占着就结束它（2026-09-19 踩坑：孤儿 vite 顶死后续所有启动，且失败全发生在隐藏控制台里、无任何可见报错）；被非 node 程序占用则说明白后失败，不抢。
- **脚本编码**：两个 `.vbs` 必须存为 **UTF-16LE（BOM）**。Windows Script Host 不认 UTF-8——无 BOM 时按 ANSI/GBK 误读中文，报「未结束的字符串常量」（2026-09-16 踩坑并修复）；带 BOM 则直接报「无效字符」。GBK/ANSI 虽也能跑，但绑死系统区域设置（换英文系统即失效），故不用。改动后务必确认编码（VS Code 状态栏 / 记事本另存为「Unicode」），别整文件重写成 UTF-8。
- **README**：新增「启动」一节——dev 启动器与安装包的差异、快捷方式建法、常见等待时长预期。
- **不做**：自动更新（updater）、版本号管理流程、绿色版数据目录重定向。

## 二、实现增量与验收

- 仓库根加 `启动工笔.vbs`；README 增「启动」一节；构建一次并记录产物路径于工单 #34 评论。
- 本机 MSI 打包在 WiX `light.exe` 起不来（环境问题），固定 `--bundles nsis` 出 NSIS 安装包＋独立 exe；`mainBinaryName`＝工笔（独立 exe 名不再叫 app.exe）。
- 验收（冒烟）：双击 vbs → 无终端窗口 → 应用窗口出现；安装包安装 → 桌面图标 → 纯 GUI 启动；`npm run tauri build` 产物路径与 README 一致。

## 三、判死与复活信号

| 判死 | 复活信号 |
|---|---|
| 自动更新（tauri updater） | 真要频繁分发给别人 |
| 每次升级自动重打包的脚本 | 备份快照跟不上的痛真出现 |
| dev 启动器进度界面（编译日志） | 等待时长频繁让人怀疑卡死 |
