# 视觉系统

> 工单 [UI 视觉打磨：全局＋编辑器外观 #35](https://github.com/q956085398-netizen/MyAINovel/issues/35) 落地；方向由 [UI 视觉调研：参考方向产出 #39](https://github.com/q956085398-netizen/MyAINovel/issues/39) 产出、**用户选定「乙 · 现代通透」**。
> 基线：设计共识 §一（Windows 优先、界面全中文、纯个人使用）、[个性化设置.md](./个性化设置.md)（主题三态＋六套编辑器背景＋排版五项）、[编辑器渲染层.md](./编辑器渲染层.md)（callout 卡片与内联图）。
> 定位：全应用的**外观刻度**——间距/圆角/阴影/动效/字号/图标六组值收敛成一套 token，界面各处只引用 token。**布局与信息架构不动**，色相不动。

## 一、决议总览

| 问题 | 决议 |
|---|---|
| 结构参数从哪来 | 方向由 #39 三选一（甲 纸墨精修｜**乙 现代通透**｜丙 紧凑专业），用户选定乙；预览页见 `research/ui-visual-direction-preview.html`（`research/ui-visual-direction` 分支） |
| 值放哪 | 全部落成 `App.css` 根上的 CSS 变量（浅色一套值、深色整组重定义），沿用 #24 的变量组机制 |
| 硬编码怎么办 | 圆角、阴影、界面字号**一处不剩**（可 grep 自查，例外见 §九）；过渡时长全走 `--dur`（例外＝AI 光标闪烁，那不是过渡）；**布局级**间距走 `--sp-*`，控件内部 <8px 的贴合缝隙保留字面量 |
| 图标 | 引入 `lucide-react`（ISC），统一 18px／1.75 描边，只从 `app/src/icons.tsx` 出 |
| 动效 | 一处 180ms 呼吸节奏（`--dur`／`--ease`）；位移与缩放只出现在浮层入场；`prefers-reduced-motion` 下归零 |
| 深色怎么分层 | 浅色＝阴影表达高度；深色＝**阴影退场，表面提亮一档**（浮层留一档重阴影与背后分离） |
| 编辑器 | 仍是「纸」不是「卡片」：纸面加 1px **内描边**（不是阴影），与外围浮起区分；六套纹理照旧 |

## 二、token 层（`app/src/App.css` 顶部）

| 组 | 变量 | 值 | 用途 |
|---|---|---|---|
| 间距 | `--sp-1…--sp-8` | 4 / 6 / 8 / 12 / 16 / 24 / 32 / 40px | 布局级 gap/padding/margin（4px 基准，主档 8~40） |
| 圆角 | `--r-ctl` | 8px | 控件：按钮、输入、下拉、导航项 |
| | `--r-card` | 10px | 卡片、表格、看板、画布、上下文菜单 |
| | `--r-dialog` | 14px | 对话框、图片查看器 |
| | `--r-inner` | 6px | 嵌套面：封面缩略图、内联图、callout 标题 |
| | `--r-tiny` | 4px | 行内小件：行内 code 底、进度条、原图 |
| | `--r-pill` | 999px | 徽标、胶囊、计数角标 |
| 阴影 | `--sh-1` | `0 1px 2px rgba(43,42,38,.06)` | 静置卡片（书封、列表卡、侧卡、导出模板） |
| | `--sh-2` | `0 4px 12px rgba(43,42,38,.10)` | hover 抬起（卡片/按钮/封面卡） |
| | `--sh-3` | `0 16px 48px rgba(43,42,38,.22)` | 浮层（对话框、上下文菜单、查看器） |
| | `--sh-media` | 浅色＝`--sh-2` 的值；深色＝`0 4px 12px rgba(0,0,0,.5)` | **浮在封面图上的控件**（设封面、更换封面）：背后是任意图片而非本应用的表面，深浅两主题都得与背后分离，因此不跟 `--sh-2` 一起退场 |
| 动效 | `--dur` / `--ease` | 180ms / `cubic-bezier(.2,.8,.2,1)` | 全站唯一节奏 |
| 字号 | `--fs-micro` / `--fs-sub` / `--fs-ui` / `--fs-md` / `--fs-lg` / `--fs-title` / `--fs-page` | 11 / 12 / 13 / 15 / 17 / 19 / 22px | 界面层级（例外：`.brand` 26px、封面占位 42px 两个展示尺寸；callout 内的 `1.05em/0.88em/0.8em` 随正文字号缩放） |

- **深浅两套值**：深色组把 `--sh-1/--sh-2` 设为 `none`、`--sh-3` 换成纯黑重阴影，其余色值沿用 #24 的深色组。
- **状态色三档**（方向乙要求，实现落点）：hover＝`--surface-hover`（列表行卡、表格行、项目导航、上下文菜单项一律走它，深浅两主题都成立）＋描边变色；hover 抬起＝`--sh-2`；选中/当前＝`--accent-soft` 底＋`inset 3px 0 0 var(--accent)` 朱砂条；禁用＝`opacity:.5`。
- **间距归并到什么程度**：页面留白（`--sp-7/--sp-8`，`.page` 与 `.project-page` 都走它）、副页签、页头下距、按钮与行卡过渡已归刻度；**卡片内距、若干纵向 gap 与个别外边距尚未归**——`gap`/`padding`/`margin` 三组里仍带 ≥8px 字面量的声明共 **62 处**（口径：`node -e` 扫 `App.css`，`var()` 取值不算），集中在 `10px`（×38）与 `14px`（×21）两档，随遇随收；本 spec 不假装它们已经归零。

## 三、图标体系

- **来源**：`lucide-react`（ISC 许可，tree-shakeable，24px 网格线性图标）。这是本应用除 CodeMirror/React 外的第一个人工引入依赖——理由是图标曾是纯文本字形（`⚙`、`×`、`✓`），没有体系可言。
- **一处出口**：`app/src/icons.tsx` 导出 `<Icon as={Glyph} />`，默认 `size=ICON_SIZE`(18)、`strokeWidth=ICON_STROKE`(1.75)；**按钮内图标传 `size={ICON_SIZE_DENSE}`(16)**（按钮文字 13px，18px 图标会比文字重；本 spec 明确把按钮算作密集控件，是方向乙「正文内联可 16px」的延伸）——尺寸与描边只在这一处定义，调用点不写字面量。`Glyph` 类型一并导出，供板块→图标映射表标注；画布自绘节点图形（`RelationshipCanvas`）不在图标体系内。
- **落地范围**（本轮）：侧栏四项板块＋AI 助手＋设置、返回类按钮（`ArrowLeft`）、弹窗关闭（`X`）、采纳态（`Check`）。
- **不落地**：不用彩色图标、不做图标按钮组、不给每个按钮都塞图标（只给导航与「返回/关闭/采纳」这三类）。
- 描边随尺寸收细有据：Obsidian 官方图标表 14/16px 用 2、18px 用 1.75、32px 用 1.25（越大越细）；本应用取 18/1.75。

## 四、动效

- **一处节奏**：所有 `transition` 引用 `--dur`（180ms）与 `--ease`。180ms 落在 Windows 11 动效 167ms 与 Material 3 Medium 之间。
- **做什么**：hover 变色与阴影抬起、切板块淡入（`fade-in`）、浮层入场（`fade-in` ＋ `pop-in` scale .98→1）。
- **不做什么**：位移不用于传达信息、不做加载动画、不做按钮按下回弹。
- **守卫**：`@media (prefers-reduced-motion: reduce)` 下动画与过渡时长归零（直接落终态，状态仍可辨——因为颜色/描边本身就是信息载体）。

## 五、两主题与六套纹理

- **浅色**：阴影三档齐全，卡片轻微浮起，强调色 `#a8432f`。
- **深色**：阴影退场（`--sh-1/2: none`），层级改由**表面提亮**表达（`--panel` 亮于 `--bg`，hover 走 `--surface-hover`）；强调色降饱和提亮为 `#cf7a62`（既有值）；浮层保留 `--sh-3` 与背后分离，浮在封面图上的控件保留 `--sh-media`（图片背后没有主题色阶可用，退场就粘连）。
- **六套背景**：素纸/宣纸/羊皮/豆沙绿/竹青/暮山**一律照旧**（#17 的机制与判据不变）；本轮的改动只在纸面**内描边**——编辑器是沉浸式纸面，不用卡片阴影，免得跟管理界面的浮起语言打架。深色下浅纹理仍按旧规自动压暗。

## 六、编辑器外观

- **纸面**：`.editor-container` 1px 内描边（`inset 0 0 0 1px var(--line)`），无外阴影。
- **callout 卡片**（#32）：圆角随 `--r-card`，`cm-callout-first/last` 的首尾圆角同步；卡片内标题与图标用 `--r-inner`。
- **内联图与查看器**（#31）：编辑器内图 `--r-inner`（贴纸面），原图查看器面板 `--r-dialog`、图自身 `--r-tiny`。
- **排版五项**（#33）：字号/行距/对齐/首行缩进仍是视图层显示、不改 md；由 `editorTheme.ts` 注入，与本 spec 的 `--fs-*`（界面字号）**互不干涉**：编辑器正文走用户的排版设置（15/17px 默认），界面 chrome 走 `--fs-*`。

## 七、判死与复活信号

| 判死 | 复活信号 |
|---|---|
| 每个板块各自的圆角/字号（局部 token） | 真觉得看板和编辑器需要两套刻度 |
| 图标做成图形化彩色图标 | 单色线性真读不出来 |
| 弹窗以外的元素做入场动画 | 切页/切看板真觉得缺一个过渡 |
| 阴影做到第四档 | 真出现「浮层上还有浮层」的场景（`--sh-media` 不算第四档：它只是「浮在图片上」这一处的深浅别名，浅色值就是 `--sh-2`） |
| 微间距也强行归到刻度 | 控件内部布局真出问题 |
| 编辑器纸面改成卡片（外阴影＋独立容器） | 沉浸式用久了想改成「纸张式」 |
| 把界面字号并进排版设置 | 真想界面字号跟正文一起调 |

## 十、依据（一手来源）

| 本 spec 的取值 | 依据 |
|---|---|
| 圆角分档（控件小、卡片中、浮层大） | Windows 11：窗口/flyout/dialog 8px、页内控件 4px（`OverlayCornerRadius=8`、`ControlCornerRadius=4`）；Obsidian `--radius-s/m/l/xl` = 4/8/12/16 |
| 阴影三档 + 恒定 1px 描边 | Windows elevation 数值分层（Dialog 128 / Flyout 32 / Card 8 / Control 2）；SiYuan 弹窗 `0 8px 24px rgba(0,0,0,.2)` |
| 深色「阴影退场、表面提亮＋1px 描边」 | SiYuan 暗色改用 `rgba(0,0,0,.8)` 阴影＋`0 0 0 1px rgba(255,255,255,.12)` 白描边；Windows 同 elevation 在暗色下阴影强度另配 |
| 180ms 动效 | Windows 11 250/167/83ms 三档；Material 3 Short4=200ms、Medium1=250ms——180ms 取两者之间 |
| 图标 18px／1.75 描边 | Obsidian 官方图标表：14/16px → 2、**18px → 1.75**、32px → 1.25（越大越细）；SiYuan 231 个图标统一 `stroke-width="1.7"` |
| 4px 间距基准 | Obsidian `--size-4-N`（4px 网格）、SiYuan 4px 基准、Typora 正文 `16px/1.5` |
| 界面 13px 字号基准 | Obsidian UI 字号 12/13/15/20（正文 16）；Windows 字阶 12/16、14/20 |
