# 书库新建与展示

> 工单 #17 决议（**grilling：三轮问答由用户逐项拍板**）。基线：ADR 0002（文件为唯一数据源、不搬动不改写既有文件）、设计共识 §三（根目录散文件/一书一文件夹两布局兼容）、#13 拆书 yaml schema（懒生成、条目收口）、#4 构思数据模型（`项目/` 一书一文件夹、`create_project` 纪律）。
> 定位：软件「**可共用 OB 库、不依赖 OB 库**」——库内能新建书、无库能新建库；书库与项目列表上展示模式（封面网格/书名列表）与封面。封面是全应用第一处图片渲染。

## 一、决议总览

| 问题 | 决议 |
|---|---|
| 新建能力 | 库内「新建书」＋无库「新建库」；**不内置默认库**（库位置自己控） |
| 新建书落点 | `《书名》/`＋模板初始稿 `拆书.md`（库根 `拆书模板.md` 套用、`{书名}` 替换，模板缺失回退空文件）；yaml/附件懒生成；同名报错不续号；建后直进编辑器 |
| 新建库 | 选空文件夹即设为当前库，**零预建**（词表/项目/灵感库全懒生成） |
| 展示模式 | 封面网格（默认）｜书名列表（沿用现有表格）；拆书库、项目列表各一偏好，项目偏好构思/书写共用 |
| 封面 | 约定文件名 `附件/封面.png\|jpg\|webp`，扫描识别、**无 yaml 键**；「设封面」按钮拷图＋手动放图同识别 |
| 对称范围 | 构思（新建项目已有，只补展示/封面）＋书写（项目列表同款、与构思共用偏好） |

## 二、新建书（拆书库）

- **入口**：书库首页「新建书」按钮；空库状态（「这个文件夹里没有找到拆书稿」）也给新建入口。
- **对话框**：只填书名。v2 起书级四项不再走弹窗——初始稿自带书档块（[拆书保存与模板.md](./拆书保存与模板.md)），填不填随人，无「赶着填表」。
- **落点**：建 `《书名》/`＋初始稿 `拆书.md`（v2：模板套用，见上表）；`.yaml` 与 `附件/` **懒生成**（首次结构化标注/首次贴图时落盘，#13 纪律）。设计共识 §三「＋.yaml＋附件/」的字面按懒生成收口，原文已修订。
- **同名**（`《书名》/` 已存在）：报错让人裁决，**不自动续号**（同 `create_project`）。
- **建后**：直接进拆书编辑器。
- 散文件书（根目录 `.md`）**不提供新建入口**——新建一律一书一文件夹。

## 三、新建库

- **入口两处**：①无库空态（三个板块的 empty-state）给「打开库文件夹｜新建空库」双按钮；②设置面板「库位置」的「新建」（见 [个性化设置.md](./个性化设置.md) §五）。
- **动作**：选一个空文件夹 → 设为当前库（`gongbi.libraryPath`）。与「打开库」的实际动作同款，只有文案与意图不同。
- **零预建**：不建任何结构——`词表.yaml`、`项目/`、`灵感库/`、`校对/` 全部首用时懒生成（现行纪律原样）。
- 不做内置默认库（首次启动自动建库替用户选位置）。

## 四、展示模式

- **两档**：封面网格（默认）｜书名列表。
- **书名列表**＝现有 book-table / card-list 原样保留，不重做；「成绩/金手指」列 v2 起改从 md 书档块取数（扫描只读，取数顺序 md 书档 > yaml 残键 > 空，见 [拆书保存与模板.md](./拆书保存与模板.md) §五）。
- **封面网格卡片**：
  - 拆书：封面（或书名首字＋主题底色占位）＋书名＋一行统计（章·字·桥段）；
  - 项目：封面（或占位）＋书名＋一行统计（单元·矛盾·字数）。
- **偏好存储**：拆书库一个、项目列表一个（**构思与书写共用**后者）；localStorage 应用状态。
- 点击卡片＝打开（与现有行点击一致）。

## 五、封面

- **约定文件名**：`附件/封面.png|jpg|webp`，扫描现识别（scan 时顺带查封面文件）；同时存在多扩展名按 png＞jpg＞webp 取其一。
  - 一书一文件夹：`《书名》/附件/封面.*`；
  - 散文件书：`附件/<书名>/封面.*`（与截图粘贴同路径纪律）；
  - 项目：`项目/《书名》/附件/封面.*`（`附件/` 本就懒生成，放封面即建）。
- **无 yaml 键**：删文件即撤、在 OB 里手动放一张 `封面.jpg` 即生效——零登记、零 schema（#13 四键收口不动）。
- **「设封面」入口**：卡片悬浮按钮 → 系统选图 → Rust **拷贝**为 `附件/封面.<ext>`；已有旧封面文件则删除替换（约定单文件）。
- **首字占位**：书名首字＋主题底色，跟主题联动。
- 纪律对照：**封面是书的数据**（进创作目录、随库走）；「编辑器背景」是装修（不进）。两者方向相反，别混。

## 六、图片渲染基础设施

- 现状：全应用无 `<img>`、未开 asset 协议（capabilities 仅 `core:default`＋`dialog:default`，csp null）。
- 开通本地图片加载（asset protocol / convertFileSrc，scope 覆盖库内路径），原用于列表处的封面显示；**v2 起扩至编辑器内图片内联渲染（ADR 0005 反转原判死，见 [编辑器渲染层.md](./编辑器渲染层.md)）**。
