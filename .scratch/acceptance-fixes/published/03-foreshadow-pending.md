## What to build

伏笔可进入独立的待打磨状态，在伏笔页顶部以完整便笺呈现，整理完成后恢复原有分组与次序。状态保存在原 YAML 条目中，不改变伏笔的埋设或回收状态。

## Acceptance criteria

- [ ] 从伏笔页面进入和退出待打磨，前后端读取、编辑、重读与页面呈现形成完整路径。
- [ ] 使用独立布尔键“待打磨”；缺失或 false 为普通对象，true 为待打磨，退出移除该键；旧数据无需迁移即可读取。
- [ ] 顶部便笺完整展示已填的名称、状态、埋设与回收记录及其说明，保留原有有效操作；普通分组或筛选不会隐藏待打磨对象。
- [ ] 不改变锚点、回收、业务状态、原条目顺序或未知字段；整理完成返回原分组与次序，空待打磨区整体消失。
- [ ] 只修改原目标条目，不建立便笺副本，其他条目及未知键保持；损坏表、陈旧目标或歧义定位拒绝不安全写入。
- [ ] 复用现有原子写与冲突安全约定；手写未知字段在待打磨中编辑后仍保留，搜索和看板继续读取同一份数据。
- [ ] Rust 临时库回归覆盖进入、编辑、退出与重读、旧格式、未知字段、外部修改、损坏拒写及无副本；页面流程验证完整便笺、空区及恢复。
