# 类型/解法词表

> 工单 #10 决议（用户已授权代理给最优解，事后否决即可；v1 落地时验证）。
> 词表是桥段跨书筛选（「掉马甲有多少种解法」）与构思爽点类型圈共用的词汇基础，两张脸共用一套词。

## 决议

### 治理模式：混合——种子起步、自由生长

- 内置**类型**种子起步（14 词，见下），解决「起步不冷场」；**解法不设种子**——解法是个人拆书攒下的写法花样，没有通用词可言
- 词表**不做闸门**：类型与解法都可自由输入，不校验、不拦截；词表只做提示
- **增长靠使用**：库内已标注的类型/解法自动进入提示列表（运行时聚合，见下），打错的手滑词不会污染文件
- **不做自动同义词归并**（「掉马甲」与「马甲掉了」是否同一个词只有人能判断）；防增殖靠输入提示让人自然复用既有词，归并动作留给人手改 yaml

### 存储：库根「词表.yaml」

- 词表是用户数据不是应用配置（ADR 0002），放库根、Obsidian 可读可改
- 形态（中文键，与拆书 yaml 同一套读写约定）：

  ```yaml
  类型:
    - 掉马甲
    - 打脸
  解法: []
  ```

- **首次使用自动落盘种子版**（第一次打开桥段标注面板、或第一次跑 AI 标注命令时）；此后**应用只读不写**，增删词由用户在 Obsidian 里完成——用得多、改得少的东西不值得做管理界面，v1 不做应用内词表编辑
- 损坏时**显式报错**（不覆盖、不静默重建，沿用「扫描失败显式报错」的先例）；前端提示后输入不受影响（词表只是提示），归并/修复留给人

### 提示的合成

提示列表 = 词表.yaml 的词（**文件序在前**）＋ 库内已用词（**按使用次数降序**，同频按字典序），去重。文件词与已用词合在一个列表里，前端用原生 datalist 呈现。

### 跨板块

- v1 落地两处：
  - 拆书「桥段标注」面板：类型/解法输入挂词表提示（datalist）
  - AI「建议类型/解法标注」命令：提示词注入词表类型（截前 60 个防提示词膨胀），让 AI 优先复用既有词、避免增殖
- 将来：构思板块的类型圈面板复用同一份 yaml、同一套加载命令，不再另起词表
