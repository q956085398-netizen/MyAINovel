# 导出与发布 · 正文导出与发布前校对

> 工单 #14 决议（**代理最优解、用户未事前授权、可事后否决**——否决即重开本单重议）。
> 基线：ADR 0002（文件为唯一数据源、派生数据不污染创作文件）、ADR 0003（不碰一键生成）、#5 书写编辑器（书写页不提供导出、本地校对判死并在此复活）、#4 构思数据模型（无卷）、#12 索引与重建（无索引现扫）。
> 本文件定「把正文投递到发布渠道」的形态：导出产物、清洗规则、渠道模板、发布前校对。

## 一、定位与边界

- **导出＝只读派生动作**：读 `正文/` 与 `项目.yaml`，只写 `导出/`，**永不改动创作文件**；删掉导出目录，重跑即得。
- **校对＝发布前的一次性体检**：只读正文，命中结果只呈现与跳回，不写任何创作数据（正文零污染，与伏笔同款纪律）。
- **入口＝书写板块的项目列表**（每本书一张卡片上的「导出/发布」），不进写作页顶栏——#5「书写页不提供导出」的落点是「码字界面零打扰」，批量派生动作属于项目层。
- 不做：AI 润色/改写（发布前校对是确定性规则，不引入模型）；自动投稿/联网发布（渠道没有开放接口，投稿是人的动作）。

## 二、导出产物

### 2.1 范围：全书｜章节区间（含单章）

- 三种范围：**全书**、**区间**（起章-止章，任一端留空＝不限）、**单章**（区间的一个特例：起＝止）。
- **无「分卷」**：卷在 #4 判死，排布的最小单位是单元；要分段发布就用区间，不必先造一个卷的概念。
- 章序只认文件名里的合规序数（#5 §2.1）：未编号文件**不进导出**，报告里列出「没有章号前缀，不参与导出」（应用不自动改名——人的文件人负责）。

### 2.2 落点：项目内 `导出/`

- 落点＝`项目/《书名》/导出/`，随项目文件夹整体搬移；**不进库根**（库根是书库扫描的地盘，且一本书的发布件属于这本书）。
- 文件名：`书名-全书-YYYYMMDD.<ext>`｜`书名-0007-0020-YYYYMMDD.<ext>`｜`书名-0007-YYYYMMDD.<ext>`（单章）；书名取 `项目.yaml` 的「书名」，缺省＝文件夹名去《》。
- **不覆盖同名文件**：已存在则续 `-2`、`-3`（截图命名同款纪律）——导出件可能被手工改过，覆盖等于毁掉人的劳动。
- `导出/` **不进任何扫描**：书库扫描跳过「项目/」整棵树、构思笔记只扫 `构思/`、写作页只扫 `正文/`，三处都不用改（这是选它的主要理由）。

### 2.3 格式：txt（默认）｜md

- **txt**：平台粘贴口径——去 frontmatter、去 markdown 标记、段间空行规范化、可选段首缩进；图片链接整条删除（txt 渠道不能带图），报告里记「本章删除 N 张图片」。
- **md**：保留 markdown 原样（只去 frontmatter），用于备份/邮件投稿/自家归档。
- 两种格式都**补章节标题行**：正文文件里没有标题（标题在文件名，#5 纪律），导出时按 `项目.yaml` 的章前缀渲染 `第7章 初入江湖`；标题为空时只写章号。

### 2.4 清洗规则（txt 口径，逐条）

| 原文 | 导出 |
|---|---|
| frontmatter 块（`---` 状态…） | 整块删除；**未闭合时整段按正文导出并警告**（不吞内容） |
| `# 标题` / `## 标题` | 去 `#` 号与前导空格，保留文字 |
| `**粗**` `~~删~~` `` `码` `` | 成对标记去标记保文字 |
| 落单的 `*`/`_`/`~`/`` ` ``（打码、算式、分隔线） | **原样保留**（只配成对的才算标记，宁可留痕不可改字） |
| `> 引用` | 去 `>` 保文字 |
| `- 项` / `1. 项` | 去标记保文字 |
| `[文字](链接)` | 保「文字」 |
| `![图](路径)` | **整条删除**（含 alt），计数入报告 |
| 代码围栏 ``` | 去围栏保内容 |
| 连续空行 | 压成一个空行 |
| 行尾空格 | 去掉 |
| 段首缩进（模板开关，默认开，v2 工单 #33） | 每段前加两个全角空格 `　　` |

- 不做「智能分段」「自动加标点」：正文长什么样是人的事；也**不重新折行**（一行一段是网文习惯，平台自己排）。

### 2.5 报告（导出后回显）

- 返回：文件路径（可打开所在目录）、章数、总字数、**每章字数**（有提示的章节直接列出，全部章节折叠展开）、警告清单——未编号文件不参与、空章、字数越界（模板下限/上限，默认下限 2000、上限 0＝不限）、删除的图片数、frontmatter 未闭合。
- 越界**只提示不拦截**（与全应用「只提示不校验」同款）。

## 三、渠道模板

- 模板＝命名的导出配置：格式（txt/md）、章节标题行（开/关）、标题模板（默认 `{章号} {标题}`，`{章号}` 由章前缀渲染）、段间空行（0/1）、段首缩进（开/关）、单章字数下限/上限（提示用）。
- **存应用状态**（应用数据目录 `导出/模板.json`），与 AI 供应商配置、每日目标同款——渠道模板是「平台习惯」不是「这本书的数据」，跨项目共用；创作目录不出现配置文件。
- 内置一个「默认」模板（txt、标题行开、段间一空行、段首缩进默认开、下限 2000）；**不预置平台模板**——平台规则会变，假装懂不如让用户存一份自己的。
- 章前缀取 `项目.yaml`（缺省 `第{n}章`），是标题模板的唯一项目侧来源；模板本身不重复存前缀。

## 四、发布前校对模式

### 4.1 触发与范围

- **只在点「发布前校对」时跑**：不实时、不驻留、不打扰（#5 判死本地校对的复活形态）。
- 范围：全书（默认）｜区间（起＝止即单章）。入口在项目列表，没有「当前章」语境；写单章就在区间里填同一个章号。只读正文，命中结果不写任何文件。未编号章也扫（结果显示文件名），校对不依赖章序。

### 4.2 三类规则（确定性，宁可漏报不可误报）

1. **敏感词**（DFA 多模式匹配）：词库＝库根 `校对/敏感词.txt`，一行一词、`#` 开头为注释；**应用不内置词表**（平台规则会变、合规责任在作者），文件不存在时提示怎么建。
2. **的地得**（内置规则，高置信小集）：动词＋「的」＋程度/结果词（「跑的快」）→ 建议「得」；状语词＋「的」＋动词（「认真的看」）→ 建议「地」。只报**表内命中**（动词表、程度词表、状语表显式列出），不猜、不做统计模型。
3. **错词**：库根 `校对/错词.txt`，一行 `错词 => 对词`（无 `=>` 的只报不改）；**内置一小撮高置信种子**（如 因该→应该、既使→即使、迫不急待→迫不及待），用户文件叠加在内置之上。

### 4.3 结果呈现与跳回

- 按章分组、按行号排序：每条＝章号＋行号＋上下文片段（命中词高亮）＋规则＋建议。
- 点一条 → **跳回书写页该章、滚动到命中处并选中命中词**（复用伏笔看板「点章跳回」的跳转管线，携带位置而非引文）。
- 顶部给计数摘要；导出页签里给「先跑一遍校对」的入口，但**不拦截导出**（校对是建议，不是闸）。

## 五、判死与复活信号

| 项 | 决议 | 复活信号 |
|---|---|---|
| 分卷导出 | 判死（卷在 #4 判死） | 真按卷发布 |
| 平台预置模板 | 判死 | 用户反复手改同一组参数 |
| 内置敏感词库 | 判死（平台规则会变，责任在作者） | 用户明确要一份起步词表 |
| 校对结果自动改写正文 | 判死（正文零污染＋ADR 0003） | 无——纪律不是偏好 |
| 导出带附件图片 | 判死（txt 渠道不能带图） | 渠道支持图文 |
| 排版级预览（所见即所得） | 不做（平台自己排） | 用户反复因排版返工 |
| AI 润色/一致性检查 | 留地图雾区「构思/书写 AI 命令集」 | 随该工单成型 |
| 导出到用户自选目录 | 判死（落点固定才回答得了「东西在哪」） | 真需要给外部编辑投稿 |
