# 人物对话

> 工单 #16 决议（**grilling：两轮问答由用户逐项拍板**）。基线：ADR 0002（文件为唯一数据源）、ADR 0003（AI 只处理人写内容、激发灵感在其内）、#5 书写编辑器、#8 人物关系画布（人物/角色卡分工、边表）、#15 AI 命令集（侧边栏命令管线与采纳闸）。
> 定位：与书内「人物」聊天找灵感（酒馆式的工笔版）。对话是**草稿纸**，不是创作数据；聊出的真金白银经采纳闸落盘。

## 一、决议总览

| 问题 | 决议 |
|---|---|
| 跟谁聊 | **仅书内人物**（带小传/关系网/类型圈，贴着这本书聊）；角色卡想聊先转生为人物 |
| 记录存哪 | **应用状态、AI 会话同库**（`sessions/` 目录，会话带人物标签） |
| 形态 | **AI 侧边栏的新会话类型**（人格系统提示，复用多供应商/流式/历史/采纳管线） |
| 人格材料 | **小传正文＋他的全部关系边＋类型圈**，后端现读组装；人物**不加**结构化字段 |
| 产出落盘 | **采纳式两去向**：「存为矛盾」（本项目）／「存为故事卡」（灵感库），只预填、人确认 |
| 正名 | **「人物对话」**（词汇表：「人物卡」是「人物」的 Avoid 词） |

## 二、对象与边界

- **仅书内人物**：`构思/人物/<人名>.md` 是对话对象；灵感库「角色卡」是全局素材、不带关系网与类型圈，v1 不直接聊（想聊先转生为人物，#8 §五）。复活信号：真想跟「还没写进书里的卡」聊。
- **不越 ADR 0003**：人物对话＝「激发灵感」的一种——AI 以人物口吻陪聊，不代写正文；落盘只进**种子类对象**（矛盾/故事卡），且经人确认的采纳闸，与「润色替换选中」「提为矛盾」同一纪律。
- 不做（v1 判死，复活信号附后见 §七）：开场白（角色先开口）、多人群聊、人物结构化口吻字段、对话记录进创作目录。

## 三、会话：AI 会话同库、带人物标签

- **存应用状态**：与现有 AI 侧边栏会话同住应用数据目录 `sessions/`，不进创作目录、不随书拷贝——对话是找灵感的草稿纸，进了 Obsidian 视野只会稀释创作文件。
- **会话多一个可选人物标签**：`{项目: 《书名》, 人物: 人名}`。标签只用于：会话列表里显示「《书名》· 人名」、再次打开时按标签重识；**旧会话无标签照常工作**（serde 缺省，向后兼容）。
- **标签失效只提示不校验**（同款纪律）：人物改名/删除、项目改名后，旧会话照常能聊（人格底座自随会话）；打开会话时按标签现查，对不上就在面板里提示一句「按原人格底座继续聊」，不回写、不清理。
- 会话内消息结构与既有 AI 会话完全一致；人格只体现在系统提示，不新增消息类型。

## 四、人格材料（后端现读组装）

- 复用 #15 的材料管线：IPC `build_ai_context` 加一条 `kind = 人物对话`，`subjects = [人名]`（一人一会话）。
- **材料口径**（一段纯文本，进系统提示而非用户消息）：
  1. 人物小传：frontmatter（分组/别名）＋正文全文（正文上限 4000 字，超出截断并注明）；
  2. 他的全部关系边：邻居人名＋类型＋描述＋秘密（沿用 `relationship_view` 的派生口径，含失效引用的告警文本）；
  3. 本书类型圈（类型清单，缺省时显式占位「（类型圈还没定）」）。
- **不塞**：正文（几十万字）、其他人物名单、排布——「跟这个人聊」不等于「替这本书开会」。
- 读不动的材料**显式报错**（沿用扫描纪律）：人物文件/边表/类型圈解析失败 → 不建会话、报错给人。
- 上限常量入 Rust、可测（与 #15 §三同款）。

## 五、提示词与入戏纪律（前端 `ai.ts`）

- 材料当系统提示底座，提示词告诉模型：**以该人物第一人称口吻回应、不跳出角色**；贴着类型圈内的世界聊，圈外话题用人物的方式岔开；不替作者写剧情正文、不出「本章应该…」式的写作建议——那是别的命令的事。
- 提示词在前端、材料在后端（#15 两处各管一段的分工原样）。

## 六、产出落盘：采纳式两去向

- **动作**：选中一段对话（一条或多条消息）→「存为矛盾」/「存为故事卡」→ 对话框预填 → 人改定 → 确认落盘。
- **只预填、不生成**（采纳闸纪律）：
  - 存为矛盾：标题预填对话首行前若干字（人改），正文＝对话摘录（每行带说话人标记），frontmatter `状态: 池中`；落在**本项目** `构思/矛盾/`。同名已存在 → 报错让人裁决（#9 纪律，不自动续号）。
  - 存为故事卡：标题同上，一句话核心预填摘录首行、正文＝对话摘录，来源预填「人物对话·《书名》/人名」；落在**灵感库**。同名报错同款。
- 落盘成功只提示，不自动跳转（v1 简化；复活信号：用户抱怨找不到存哪了）。
- 不做：从对话直接建单元/人物/正文（提级链路保持单向：对话 →（人拍板）→ 矛盾 → 单元）。

## 七、判死与复活信号

| 判死 | 复活信号 |
|---|---|
| 角色卡直接进对话 | 真想跟还没写进书里的卡聊 |
| 对话记录进创作目录 | 反复手动拷聊天记录进书 |
| 人物加口吻/知识边界字段 | 真觉得 AI 学不像、反复往小传堆口吻说明 |
| 开场白（角色先开口） | 真用出「每次都要自己先说」的烦 |
| 多人群聊 | 真想同时跟两个角色对戏 |
| 落盘后自动跳转 | 抱怨找不到存哪了 |

## 八、v1 代码增量

- **Rust**：
  - `ai_context.rs`：`kind = 人物对话` 的材料组装器（小传＋边＋类型圈，上限常量）；`build_context` 走 `subjects`。
  - `ai.rs`：`ChatSession` 加可选 `人物` 标签（`{项目, 人物}`，serde 缺省向后兼容）。
  - IPC：`build_ai_context` 扩一条 kind；会话读写沿用既有四条。
- **前端**：
  - `ai.ts`：人物对话的提示词（入戏纪律）。
  - `AiSidebar.tsx`：从人物进入建会话（人格系统提示）；打开会话按人物标签现查、失效给提示（不回写）；选中消息的「存为矛盾/存为故事卡」采纳动作＋预填对话框（**落盘前显式查同名，重了报错让人裁决**——不走后端续号，续号会静默绕过采纳闸）。
  - `NoteList.tsx`（人物名单行）与 `RelationshipCanvas.tsx`（选中侧栏）：「跟 TA 聊」入口。
- 测试：Rust 侧材料组装（截断/占位/边失效告警/读不动报错）＋会话标签往返与旧会话兼容。

## 九、对其他工单的影响

- **#8 人物关系画布**：画布侧栏多个「跟 TA 聊」入口；边表、人物文件字段不动。
- **#15 AI 命令集**：材料管线多一条 kind；「人物对话」不入命令按钮排布（它从人物页签进，不从命令条进）。
- **#4 构思数据模型**：无文件布局变化（对话在应用状态）。
- **#9 故事卡转生**：故事卡多一个来源（「人物对话」采纳），关联解析不受影响。
