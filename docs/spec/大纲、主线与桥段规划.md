# 大纲、主线与桥段规划

> **2026-09-19 补充**：构思增加轻量首页；「类型圈」在界面改称「读者遐想（类型圈）」；每张桥段卡可记录多组「类型 → 解法」，但不强制填写。桥段、单元等内容卡默认完整展开正文和结构字段，可由用户手动收起；任意卡片均可进入「待打磨」便笺区。详见 [产品设计补遗](../产品设计补遗.md) 与 [工作台与卡片呈现](./工作台与卡片呈现.md)。

> 2026-09-16 用户逐项确认。基线：[设计共识](../设计共识.md) 的体验原则、ADR 0002（文件为唯一数据源）、ADR 0003（AI 边界）、ADR 0004（原子写与版本指纹）、[构思数据模型](./构思数据模型.md)。
>
> 本规格补足构思到书写的规划闭环，并取代《构思数据模型》中「单元内桥段只写自由文本、不做结构化字段」的旧决定。

## 一、目标与非目标

- 让作者先立全书骨架，再逐步落到单元、桥段和章节；任何一层都可晚补。
- 已保存但尚未处理的灵感、桥段与规划必须容易看见，不能因未归类而消失。
- 不以必填表单、红色告警或章节评分打断构思和书写。
- 不做自由画布、自动排主线、自动为桥段创建单元，也不把 AI 变成裁判或代笔者。

## 二、构思导航与动作层级

构思页签按创作过程分三组，自上而下显示：

1. **定书**：大纲、类型圈、人物、世界观、开头；
2. **生情节**：矛盾、桥段库、单元、排布；
3. **织张力**：伏笔、期待感、目标。

每个操作区域只保留一个主动作，且放在正在处理的内容附近。导入、刷新等次级动作不抢主色；删除等破坏性动作只在对象的上下文或确认对话框中出现。

## 三、大纲与主线

### 3.1 文件与唯一来源

```text
构思/
  大纲.md
  主线.yaml
```

- `大纲.md` 是自由书写的**大纲纸面**。首次创建可写入可删改的 `## 立意`、`## 主线总览`、`## 阶段构想`、`## 尚未解决` 标题；没有必填字段。
- `主线.yaml` 是主线图的结构化来源；大纲纸面不重复里程碑卡的结构化信息。
- 两个文件均懒生成；缺失表示尚未开始这一层规划。

### 3.2 主线.yaml

```yaml
- 名称: 为父正名
  主线: true
  里程碑:
    - 标题: 得知冤案
      变化: 主角从避祸转为追查
      读者感受: 不甘与期待
      单元: [初入京城]
      备注: 线索来自旧臣
    - 标题: 朝堂翻案
      单元: [宫变前夜, 大朝会]
```

- 一条标为 `主线: true` 的线是主线图最醒目的故事脊梁；感情线等重要情节线可按需加入同图，没有数量或必填要求。
- 里程碑的数组次序是唯一叙事次序。应用支持上下移动；关联单元只帮助定位，绝不自动重排里程碑。
- 里程碑只有标题必填；变化、读者感受、关联单元和备注均可留空。
- `单元` 是零到多个单元名的软引用。缺失、改名或删除只显示提示，不写回、不自动修复。

### 3.3 主线图

- 采用自上而下阅读的纵向故事脊梁，而非自由画布。
- 主线是一条最显眼的轨道；其他已加入的重要情节线以较细并行轨道显示，便于查看推进与汇合。
- 卡片显示标题、简短变化／读者感受、已关联单元和“待落地”状态；点击才展开备注与编辑。

## 四、桥段库与单元

### 4.1 单一桥段实体

```text
构思/桥段/<桥段名>.md
```

```markdown
---
所属单元: 初入京城
顺序: 2
起章: 5
止章: 8
情绪曲线: 压抑 → 犹疑 → 痛快
关键转折: 众目睽睽下拿出洗冤证据
期待钩子: 证据来源指向真正的幕后人
章节拍安排: 第5章代入＋信息差；第6章拉扯；第7章兑现；第8章善后＋启下
---

自由备注、片段和待解决问题。
```

- 一个无 `所属单元` 的文件就是**桥段草案**：它已有事件核心、人物、情绪或转折，但还没有归宿。
- 安排到单元时，应用只补 `所属单元` 和 `顺序`；卡片不会复制或迁进单元文件。未安排与已安排只是桥段库的筛选结果。
- 同一桥段只可属于一个单元；需要复用同一构想时，由人新建另一张桥段草案，不暗中共享编辑结果。
- 安排操作只提供既有单元，不自动创建空单元。取消安排只移除 `所属单元` 与 `顺序`，卡片回到待安排。
- 已安排桥段在单元页按 `顺序` 显示。刚安排时追加到末尾，应用可上下移动；这是桥段的叙事次序。
- `起章`、`止章` 是可选的桥段区间。它们可在真正写到这里时再填；重叠、倒置、越出所属单元区间或与 `顺序` 相悖都只提示，不阻止保存或书写。
- 单元 frontmatter 可增加可选 `情绪目标`。它是本单元最终要给读者的整体感受／高潮承诺，和按顺序呈现的桥段情绪曲线并列显示，不相互推导。
- 旧单元正文内的 `## 桥段安排` 原样保留为创作备注；不自动解析或删除。作者可按需将其中一项新建为桥段草案，避免不可靠的迁移和双写。

### 4.2 桥段库界面

- 默认打开“待安排”，始终显示数量；可筛选“全部／已安排”。
- 每张卡先展示人物或事件概述、情绪曲线、关键转折；详情、章节拍安排与备注按需展开。
- 卡片采取克制的便笺变体：轻纸感表面、细色边或小色签、清晰内容层次；不使用泛黄仿真贴纸、厚重阴影或满屏彩色便签，以兼容现代通透的浅／深主题。

## 五、书写时的本章意图

1. 书写页先按章节序数查找所属单元，再在该单元的已安排桥段中查找覆盖本章的桥段区间。
2. 命中时，在可折叠的“本章意图”卡片展示 `单元 → 桥段`、单元情绪目标、情绪曲线、关键转折、期待钩子和章节拍安排。
3. 未命中桥段或单元时，仅显示低干扰文案：“本章还没有设定写作意图，可以先自由写；形成明确剧情后，再整理为桥段草案。”不显示告警色、未完成数或补填按钮，也不影响保存。
4. “AI 陪看本章”只由人主动发起，读取已写正文与本章意图，按“已兑现的意图／可能遗漏／值得自己回答的问题”给简短反馈；不改正文、不评分。作者明确要求时，才可基于其已有素材提出下一拍的备选思路。

## 六、灵感速记

- 灵感页顶部常驻多行速记框；`Ctrl + Enter` 提交，普通 `Enter` 换行，并保留“收下灵感”主按钮。
- 提交立即创建未分类卡片，完整输入存为正文，首句截取为临时标题；标题、类别、来源、标签和关联均可之后再补。
- 待整理灵感始终显示在灵感页顶部并带数量，只有作者主动归类后才离开该区。

## 七、验收

- 空项目可不创建任何新增文件；打开大纲、主线图、桥段库都不因文件缺失报错。
- 大纲纸面和主线图各有且只有自己的信息来源；单元页、桥段库、书写页不复制桥段内容。
- 主线里程碑、桥段次序均由人工明确调整；单元关联、章节区间不自动改变它们。
- 任何情绪、转折、章节拍、章节区间都可留空；异常只提示，写作和保存始终可继续。
- 速记可以不填标题和分类即保存，且保存后立刻可见、可重新打开整理。
- AI 陪看没有自动执行入口、没有章节分数，也不会写回正文或规划文件。
